# Umwelt RP — журнал ошибок и исправлений (BUGFIX_LOG)

Накопительная база знаний: что ломалось, почему, как исправили и как не повторить.
Связан с `docs/РУКОВОДСТВО.md` (правила кода, раздел 7 «Частые ошибки»).

## Правила ведения

1. **Записи не удаляются и не переписываются.** Если позже выяснилось новое — дописать в запись строку
   «Дополнение (дата): …», а не править старый текст.
2. Пишем всё: ошибки, недочёты, уязвимости, потенциальные проблемы, ошибки процесса (сборка, инструменты).
3. Перед исправлением — поиск по журналу (по словам из названия, файлу, симптому). Похожая проблема уже была —
   ссылка «см. BF-NNN» в новой записи.
4. Только проверенное. Догадка помечается **«Предположение:»** и не пишется как факт. Если причина не
   установлена — так и пишем: «причина не установлена».
5. Новая запись — после каждого исправления, в том же коммите, что и исправление. Номер — следующий по порядку.
6. Статусы: **Исправлено**, **Открыто** (известно, не исправлено), **Обойдено** (решено обходным путём),
   **Принято** (осознанно оставлено как есть, с причиной).
7. Даты — по дате коммита. Для записей, внесённых задним числом (BF-001…BF-021), дата — день исправления по
   истории git; это отмечено как «запись внесена 2026-11-03».

## Записи

### BF-001 · Быстрые сообщения терялись в сети · Исправлено
- Дата: 2026-11-01 (версии 0.1–0.4; точный коммит не записан — запись внесена 2026-11-03)
- Причина: позиции и ввод шли по «ненадёжному» каналу ENet; при нагрузке ENet снижал пропускную способность
  (throttle) и отбрасывал пакеты.
- Место: `scripts/net.gd` (отправка), `scripts/game.gd` / `game_screen.gd` (приём снимков).
- Последствия: рывки и «замирания» чужих игроков, потерянные действия.
- Исправление: быстрые сообщения отправляются по каналу 1 в надёжном режиме (`Net.I.send_fast`,
  `SceneMultiplayer.send_bytes` + TRANSFER_MODE_RELIABLE); плавность — интерполяцией снимков (`NetClock`).
- Результат и проверка: сетевой тест с 3 и 10 клиентами (`nettest`, `mp.sh`) — «ИТОГ: OK»; владелец на двух
  телефонах подтвердил: «Синхронизация очень хорошая».
- Профилактика: правило кода 6 в руководстве — канал 1 не переводить на «ненадёжный».

### BF-002 · Метод лаунчера `_get` перекрывал встроенный · Исправлено
- Дата: 2026-11-01 (запись внесена 2026-11-03)
- Причина: функция загрузки файла в лаунчере называлась `_get` — это встроенный виртуальный метод `Object`
  (доступ к свойствам). Godot вызывал её не по назначению.
- Место: `launcher/launcher.gd`.
- Последствия: лаунчер работал неправильно (точные симптомы не записаны).
- Исправление: функция переименована в `_fetch`.
- Результат и проверка: лаунчер проверен со скачиванием манифеста и пакета, проверкой SHA-256 и подключением пакета.
- Профилактика: свои функции не называть именами встроенных `_get`, `_set`, `_init`, `_notification` и т.п.
  Лаунчер меняется только вместе с APK — ошибка в нём дорогая.

### BF-003 · Статические свойства с геттерами не работали · Исправлено
- Дата: 2026-11-01 (запись внесена 2026-11-03)
- Причина: в GDScript 4.4 статическая переменная с геттером не дала нужного поведения для адреса сервера.
- Место: `scripts/boot.gd`.
- Последствия: адрес и порт сервера через такое свойство не читались как нужно (точные симптомы не записаны).
- Исправление: вместо свойств — статические функции `Boot.host()` и `Boot.port()` (читают Engine meta).
- Результат и проверка: подключение к серверу Hetzner с двух телефонов.
- Профилактика: для «вычисляемых» статических значений использовать функции.

### BF-004 · «Нельзя вывести тип» — ошибка разбора скрипта · Исправлено, повторялось
- Дата: впервые 2026-11-01; повторы 2026-11-02 (запись внесена 2026-11-03)
- Причина: `var x := <выражение типа Variant>` — Godot не может вывести тип (результат `JSON.parse_string`,
  элемент массива, `surface_get_format`, `duplicate()`), а предупреждение в проекте считается ошибкой.
- Место: впервые `launcher/launcher.gd` (JSON); повторы — временные сцены превью (`editor.gd`: `fmt`,
  `car_gen.gd`: `v`, `k`, `x`, `dz`).
- Последствия: скрипт не загружается целиком; в игре это был бы полностью нерабочий экран или режим.
- Исправление: явный тип (`var fmt: int = …`, `var v: Array = …`) или `var d = …` без вывода.
- Результат и проверка: `check.sh` (проверка разбора всех скриптов) — без ошибок; автотесты проходят.
- Профилактика: для значений из словарей, массивов, JSON и API Mesh всегда указывать тип явно. Перед пушем —
  проверка разбора всех скриптов и `--audit`.

### BF-005 · Неверный регистр имени репозитория в адресах · Исправлено
- Дата: 2026-11-01, версия 0.2 (коммит 14e85c5) (запись внесена 2026-11-03)
- Причина: репозиторий переименован в `Umwelt-RP`, а в адресах обновлений стоял другой регистр.
- Место: адреса релизов GitHub в коде и скриптах (лаунчер, сборка, сервер).
- Последствия: лаунчер и сервер могли не найти файлы обновлений.
- Исправление: все адреса приведены к точному имени `C0BecTb11/Umwelt-RP`.
- Результат и проверка: лаунчер и сервер скачивают сборки из релиза «latest».
- Профилактика: адрес репозитория брать из одного места; при переименовании — поиск по всему проекту.

### BF-006 · Серверный код попадал в пакет игры · Исправлено
- Дата: 2026-11-02, версия 0.8 (коммит 5307747) (запись внесена 2026-11-03)
- Причина: код выделенного сервера и автотестов лежал в общей папке `scripts/` и экспортировался в `game.pck`.
- Место: `scripts/server.gd` (теперь `scripts/server_only/server.gd`), `export_presets.cfg`.
- Последствия: любой, кто скачал игру, мог извлечь серверную логику (проверки, сохранения) — уязвимость.
- Исправление: серверное перенесено в `scripts/server_only/` (без `class_name`, загрузка через `load()`),
  папка исключена из экспорта Android; в `build.yml` проверка — сборка падает, если в пакете есть серверная метка.
- Результат и проверка: CI-проверка утечки (`SAVE_BAK` в `game.pck` и APK — 0 вхождений).
- Профилактика: правила кода 8–9 руководства; никаких секретов в клиенте.

### BF-007 · Ссылка из письма подтверждения ведёт на localhost · Открыто (нужно действие владельца)
- Дата: обнаружено 2026-11-01 (запись внесена 2026-11-03)
- Причина: в Supabase не задан Site URL — письмо подтверждения использует адрес по умолчанию `localhost:3000`.
- Место: настройки Supabase (Authentication → URL Configuration); страница — ветка `gh-pages`.
- Последствия: игрок видит пустую страницу после перехода по ссылке (вход при этом работает).
- Исправление: подготовлена страница «Почта подтверждена» (`gh-pages`). Осталось владельцу: включить GitHub
  Pages (`gh-pages` / root) и указать Site URL `https://c0bectb11.github.io/Umwelt-RP/`.
- Результат и проверка: не проверено — ждёт настройки.
- Профилактика: при подключении сервисов аутентификации сразу задавать адреса перенаправления.

### BF-008 · Нет доступа к секретам и Pages GitHub из среды разработки · Обойдено
- Дата: 2026-11-01 (запись внесена 2026-11-03)
- Причина: прокси среды разработки запрещает запись в API GitHub (секреты, Pages, настройки).
- Место: процесс сборки и выпуска.
- Последствия: ключ подписи APK нельзя положить в секреты; Pages нельзя включить автоматически.
- Исправление (обход): ключ подписи хранится в кэше GitHub Actions (CI обновляет его раз в неделю);
  Pages включает владелец вручную.
- Результат и проверка: сборки APK подписываются одним ключом.
- Профилактика: долг записан в руководстве (раздел 8) — перенести ключ в секреты вручную. Потеря кэша =
  новый ключ = переустановка приложения у всех.
- Связано: BF-015, BF-016.

### BF-009 · Ложный результат автотеста из-за старого лога · Исправлено
- Дата: 2026-11-01 (запись внесена 2026-11-03)
- Причина: скрипт проверки читал файл лога от предыдущего запуска.
- Место: локальные скрипты проверки (`/tmp/claude-0/rp/*.sh`, не в репозитории).
- Последствия: можно было принять упавший тест за прошедший.
- Исправление: перед каждым запуском лог удаляется (`rm -f …/aud.log`).
- Результат и проверка: результат «ИТОГО: N прошло, 0 ошибок» берётся из свежего вывода.
- Профилактика: проверочные скрипты всегда начинают с чистого лога.

### BF-010 · Команда остановки Godot убивала сам терминал · Исправлено
- Дата: 2026-11-01 (запись внесена 2026-11-03)
- Причина: `pkill -f godot` ищет слово в полной командной строке — под него попадала и оболочка с этим словом.
- Место: локальные скрипты сетевых тестов.
- Последствия: прерывание проверки, «висящие» процессы, занятые порты.
- Исправление: `pkill -x godot` (точное имя процесса).
- Результат и проверка: сетевые тесты запускаются повторно без конфликтов портов.
- Профилактика: для остановки процессов — `pkill -x <имя>`.

### BF-011 · Старые вещи пропали бы после смены одежды · Исправлено (миграция v2)
- Дата: 2026-11-02, версия 0.11 (коммит d9c57b8)
- Причина: старая одежда (кепки, куртки, рюкзаки) удалена из игры; у игроков в сохранении оставались её id.
- Место: `scripts/game.gd` — `migrate()`, `wear_from()`, `SAVE_VERSION`.
- Последствия: без миграции — неизвестные вещи в инвентаре и голые персонажи (у всех было только «джинсы»).
- Исправление: `SAVE_VERSION = 2`; при загрузке старого мира неизвестные вещи убираются, недостающие футболка
  и кеды выдаются.
- Результат и проверка: автотест «Сохранение v1: старая одежда убрана, выдана футболка и кеды, вода на месте» — OK.
- Профилактика: удаляя предметы, всегда писать шаг миграции и тест на старое сохранение (правило кода 4).
  Откат на версию до 0.11 с сохранением формата v2 — опасен (см. «Версии и откат» в руководстве).

### BF-012 · Предметы в руке смещены относительно кисти · Исправлено
- Дата: 2026-11-02, версия 0.11 (коммит d9c57b8)
- Причина: у моделей Quaternius в glTF поза покоя скелета (rest) не совпадает с позой привязки одежды (bind pose).
  Расчёт положения от rest давал сдвиг (на превью кепка «висела» над головой, очки уходили внутрь головы).
- Место: `scripts/character.gd` — `_set_weapon()` (положение оружия на кости `Wrist.R`).
- Последствия: оружие и аксессуары в воздухе или внутри тела.
- Исправление: положение считается от bind pose из `Skin.get_bind_pose()`, а не от `get_bone_global_rest()`.
- Результат и проверка: демо-снимок `--demo=armed` — бита, нож, лом, молоток, пистолет в руках.
- Профилактика: всё, что крепится к костям этих моделей, считать от bind pose кожи.

### BF-015 · Сборка 0.14 «красная»: метки версий запрещены · Обойдено
- Дата: 2026-11-02, версия 0.14 (коммит 0f63e02), исправлено в 0.15 (коммит 98a7331)

- Последствия: сборка помечена как упавшая (игра и сервер при этом обновились — шаг был последним).

- Результат и проверка: сборки 0.15 и 0.16 — успешно; описание релиза содержит версию и коммит.
- Профилактика: новые шаги CI, пишущие в репозиторий, ставить с `continue-on-error` до первой успешной проверки.
- Связано: BF-008, BF-016.

### BF-017 · Автоправка удалила лишние функции `world_view.gd` · Исправлено до коммита
- Дата: 2026-11-02, при подготовке версии 0.16
- Причина: при удалении тумана войны скрипт вырезал текст от `_compute_vis()` до функции после `_vis_at()` —

### BF-024 · Редкий ложный откат игрока у стен и углов · Открыто
- Дата: обнаружено 2026-11-04
- Причина: не установлена.
- Место: проверка позиции от клиента в `scripts/game.gd` (`remote_input`); тест «честного игрока не откатывает
  у стен и углов» в `audit_test.gd`.
- Последствия: в одном из 9 полных прогонов аудита — 11 ложных откатов. На коде до 0.17 в 30 отдельных прогонах
  теста — 1 падение с тем же признаком, на новом — 0 из 30. Значит, ошибка была и раньше, чисткой не вызвана.
  Предположение: живой игрок у стены может изредка «дёргаться» назад; сборка CI может изредка падать на аудите.
- Исправление: не сделано.
- Результат и проверка: —
- Профилактика: при «красном» аудите на этом тесте — перезапустить и, если повторится, разбирать по этой записи.
- Заметка: один раз при завершении сетевого теста было «Unable to send packet on channel 0»; повторить не удалось
  ни на новом, ни на старом коде. Причина не установлена.
- Дополнение (2026-11-04): причина найдена и исправлено в 0.18.
  - Причина (подтверждена): телефон двигает игрока по осям — за кадр сначала X, потом Y. Когда игрок бежит
    по диагонали в выступающий угол дома, на первом кадре X упирается в угол и двигается только Y, на
    следующих — уже оба. Путь за пакет получается «лесенкой». Сервер в `_path_free` проверял путь
    короче 0.15 клетки одним шагом `_move_circle`: X сразу упирался в угол и путь считался запрещённым.
  - Последствия (подтверждены): игрока возвращает назад. Он снова бежит тем же путём и снова получает откат —
    то есть застревает у угла, пока не сменит направление. В тесте на 120 000 маршрутов так застряли
    4 маршрута, у всех бег по диагонали.
  - Исправление: `_path_free` принимает прямую или одну из двух «ступенек» (сначала X или сначала Y). Каждый
    отрезок проверяется точками через 0.05 клетки (`_segment_free`) с радиусом `PLAYER_R - 0.05`. Сквозь целую
    клетку стены или двери так не пройти.
  - Проверка:
    - 77 695 маршрутов — 0 откатов.
    - Новые автотесты:
      - «бег по диагонали в угол дома не откатывается» — 4 найденных случая; на старом коде падает,
        на новом проходит;
      - «нельзя прислать позицию за стеной или закрытой дверью» — 756 стен, 52 двери; если проверку пути
        отключить, тест ловит 808 проходов насквозь.
    - Аудит 52/0 трижды подряд; сетевой тест на 3 клиента — 0 откатов.
  - Профилактика: проверка движения на сервере должна допускать всё, что может сделать движение на телефоне
    (`move_player`); при изменении одного — проверять другое.
  - Заметка «Unable to send packet on channel 0» к этой ошибке не относится. Сообщение повторилось один раз при
    завершении сетевого теста (игроки уже выходили, итог OK). Предположение: сервер шлёт пакет только что
    отключившемуся клиенту. Не исправлялось.
