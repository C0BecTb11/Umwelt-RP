# Umwelt RP — движение данных (DATA_FLOW)

Как данные ходят между тремя частями: **телефон** (Android: лаунчер + игра), **игровой сервер** (Hetzner,
`server_only/server.gd`) и **Supabase** (аккаунты). Плюс **GitHub Releases** — откуда приходят обновления.
Составлено по коду (проверено 2026-11-04, после версии 0.19) и по самой базе (`docs/SUPABASE_MAP.md`).
Описано только то, что есть в коде. Чего нет — так и написано.

Обозначения: 📱 телефон, 🖥 игровой сервер, ☁️ Supabase, 📦 GitHub Releases.
Каналы: **HTTPS** — шифрованный; **ENet** — UDP-порт 7777, **без шифрования**: канал 0 — надёжный RPC
(`Net.send` → `_recv_rel`), канал 1 — надёжный, сырые байты (`Net.send_fast` → `_on_bytes`, от клиента не больше
4096 байт).

## 0. Общая схема

```
                 HTTPS (вход, токен, персонаж)              HTTPS (проверка токена, имя/ID/пол)
   📱 account.gd ───────────────────────────────► ☁️ Supabase ◄──────────────────────────── 🖥 server.gd
        │  (токен доступа)                          ▲                                           ▲
        │                                           │ HTTPS: черновик карты (только админ)      │
        │                                   📱 map_editor.gd                                    │
        ▼                                                                                       │
   📱 game_screen.gd ═══════════ ENet UDP 7777, без шифрования ════════════════════════════════╝
        hello(токен) → ; ← init(мир) ; in(ввод+позиция) 20/с → ; act(действия) → ; ← st 20/с ; ← ev

   📦 GitHub Releases «latest»: manifest.json, game.pck, umwelt-server.zip, umwelt.apk
        ├─ HTTPS → 📱 launcher.gd (пакет игры, адрес сервера)      ├─ HTTPS → 🖥 server/update.sh (сборка сервера)
        └─ HTTPS → 📱 game_screen.gd (напоминание об обновлении)
```

Где что **хранится** (единственный источник правды выделен):

| Данные | Где хранится | Копии |
|---|---|---|
| Аккаунт (почта, пароль) | **☁️ `auth.users`** | 📱 `user://account.cfg`: почта и refresh-токен (пароль не хранится) |
| Имя, постоянный ID, пол | **☁️ `public.characters`** | 🖥 `Player.name`, `Player.id`, `Player.look.g` в файле мира; 📱 в памяти |
| Деньги, счёт, вещи, одежда, здоровье, голод, позиция | **🖥 файл мира `server_world.json`** | 🖥 `server_world.bak.json`; 📱 только в памяти (свои — полностью) |
| Кто какой игрок (`uids`: ключ аккаунта → ID) | **🖥 файл мира** | — (никому не отправляется) |
| Карта | **репозиторий `maps/city.json`** → 📦 game.pck и сборка сервера | 🖥 открытые двери — в файле мира; 📱 карта от сервера в памяти |
| Офлайн-мир («Офлайн-тест») | **📱 `user://save.json`** | `save.bak.json`; с сервером не связан |
| Черновик карты | 📱 `user://map_draft.json` | ☁️ `map_drafts` (после «Отправить») |

## 1. Регистрация и авторизация

Всё — 📱 ↔ ☁️ по HTTPS, игровой сервер не участвует.

| Шаг | Файл, функция | Откуда → куда | Данные |
|---|---|---|---|
| Кнопка «Играть» | `launcher.gd` `_launch("server")` → `main.gd` `_start_from_launcher` → `_play_server` | 📱 | `Engine meta start_mode = "server"` |
| Уже есть сессия | `main.gd` `_play_server` → `account.gd` `refresh()` | 📱 → ☁️ `POST /auth/v1/token?grant_type=refresh_token` | refresh-токен → новый токен доступа (живёт час), refresh-токен, `user.id`, почта |
| Вход | `main.gd` `_show_login` → `account.gd` `sign_in()` | 📱 → ☁️ `POST /auth/v1/token?grant_type=password` | почта, пароль |
| Регистрация | `account.gd` `sign_up()` | 📱 → ☁️ `POST /auth/v1/signup` | почта, пароль; если в Supabase включено подтверждение почты — сессии нет, игрок видит «отправили письмо» |
| Сохранение сессии | `account.gd` `_take_session()` → `_save()` | 📱 → `user://account.cfg` | почта, refresh-токен (токен доступа — только в памяти) |
| Есть ли персонаж | `main.gd` `_after_login` → `account.gd` `load_character()` | 📱 → ☁️ `GET /rest/v1/characters?select=id,name&user_id=eq.<свой>` | ответ: `id`, `name` (RLS отдаёт только свою строку) |
| Создание персонажа | `main.gd` `_show_create_character` → `account.gd` `valid_name()`, `create_character()` | 📱 → ☁️ `POST /rest/v1/characters` | `user_id`, `name`, `gender`; `id` база выдаёт сама; ошибки `23505` (имя занято), `23514` (формат) |
| Админ ли | `main.gd` `_after_login` → `account.gd` `check_admin()` | 📱 → ☁️ `POST /rest/v1/rpc/is_admin` → `user://editor.cfg` | `true/false`; только для кнопки редактора карты |
| Выход из аккаунта | `account.gd` `sign_out()` | 📱 | стирает токены в `account.cfg`; запрос в Supabase не отправляется |

Ключ API в игре — только publishable (`Boot.SUPABASE_KEY`). Все проверки прав — правилами базы (RLS).

## 2. Подключение к игровому серверу

| Шаг | Файл, функция | Откуда → куда | Данные |
|---|---|---|---|
| Адрес сервера | `launcher.gd` `_launch` → Engine meta `server_host`/`server_port` → `boot.gd` `host()`/`port()` | 📦 manifest → 📱 | `server.host`, `server.port` из манифеста (по умолчанию в `boot.gd` — 2.31.45.237:7777) |
| Соединение | `main.gd` `_connect_game` → `net.gd` `join()` | 📱 → 🖥 ENet | — |
| «Привет» | `game_screen.gd` `_on_connected` | 📱 → 🖥 `hello`, канал 0 | `token` (токен доступа Supabase), `legacy` и `uid` (оба — `Profile.uid`, случайный id телефона), `nick` (`Profile.nick`), `build` |
| Проверка сборки | `server.gd` `_handle_net` (`hello`) | 🖥 → 📱 `bye` | при несовпадении `build` — отказ с причиной |
| Проверка токена | `server.gd` `_verify` → `_sb("/auth/v1/user")` | 🖥 → ☁️ HTTPS | заголовки: publishable-ключ + **токен игрока**; ответ: `user.id` |
| Персонаж | `server.gd` `_verify` → `_sb("/rest/v1/characters?select=id,name,gender&user_id=eq.…")` | 🖥 → ☁️ HTTPS, тем же токеном игрока | `id`, `name`, `gender` |
| Вход в мир | `server.gd` `_enter` → `game.gd` `join_player(key, name, id, gender)` | 🖥 | ключ `sb:<user_id>` → `uids`; имя и пол перезаписываются из Supabase при каждом входе |
| Старый персонаж телефона | `server.gd` `_enter` | 🖥 | если у аккаунта в мире ещё нет персонажа, а `legacy` есть в `uids` — персонаж телефона переходит к аккаунту |
| Второе устройство | `server.gd` `_enter` | 🖥 → старое 📱 `bye` + отключение | «В этот аккаунт вошли с другого устройства» |
| Мир для клиента | `server.gd` `_enter` → `game.gd` `to_data_for(pid)` | 🖥 → 📱 `init`, канал 0 | `pid`, `seed`, `world`: `time`, `map` (ряды клеток с дверями, объекты, точка появления), игроки рядом (`VIEW_R` = 40): **себе — `player_data`** (всё), **другим — `player_public`**; `uids` не отправляются |
| Приём мира | `game_screen.gd` `_handle_net` (`init`) → `GameState.load_data` (`is_replica = true`) | 📱 | карта из сообщения, не из своего файла |
| Объявление | `server.gd` `_enter` → `game.gd` `msg` | 🖥 → остальным 📱 в `ev.m` | «John_Miller (5) в городе» — **всем игрокам**, независимо от расстояния |
| Таймауты | `server.gd` `_handle_net` | 🖥 | без «привета» 10 с (25 с, если идёт проверка в Supabase) — отключение |
| Выход | `net.gd` `_on_peer_disconnected` → `server.gd` (`disconnect`) → `game.gd` `leave_player` → `save_world()` | 🖥 | персонаж остаётся в мире с `connected = false` |

Режим `--noauth` (только локальные тесты): вход по `uid` и `nick` из «привета», Supabase не спрашивается.

## 3. Игровые действия

| Что | Файл, функция | Откуда → куда | Данные и проверки |
|---|---|---|---|
| Движение | `game_screen.gd` `_process` (раз в 50 мс) | 📱 → 🖥 `in`, канал 1 | `ts`, `mx`/`my` (джойстик), `run`, **`x`/`y` — позиция, посчитанная телефоном**, `fx`/`fy`, `fs` |
| Проверка движения | `game.gd` `remote_input` → `_path_free`, `_segment_free` | 🖥 | запас хода (`move_budget`, ~4.9 клетки/с), путь без стен, дверей и объектов; иначе `push_player` — откат (`force_seq` + 1) |
| Действия | `hud.gd` → `game_screen.gd` `act()` | 📱 → 🖥 `act`, канал 0 | `{"a": "attack"}`, `{"a": "interact", "c": клетка}`, `{"a": "use"/"drop"/"wear", "id": вещь}`, `{"a": "unwear", "slot": слот}` |
| Приём действий | `server.gd` `_handle_net` (`act`) → `game.actions` | 🖥 | не больше 30 за кадр с одного подключения |
| Проверка и выполнение | `game.gd` `update` → `_do_action` → `valid_action` → `_perform` (`_attack`, `_interact` + `near_cell`, `_use`, `_wear`, `_unwear`, выбросить) | 🖥 | типы полей, существование вещи (`Items.DEFS`), наличие у игрока, расстояние до двери, «жив» |
| Предсказание удара | `game_screen.gd` `act` → `game.gd` `predict_attack` | 📱 | только анимация; урон считает сервер |
| Лёгкий снимок | `server.gd` `_send_to` (раз в 50 мс) → `game.gd` `state_for` | 🖥 → 📱 `st`, канал 1 | `time`, `ts`; на каждого игрока рядом 10 чисел: `id, x, y, fx, fy, удар, присед, force_seq, hp, stamina` (**hp и stamina — только свои**, у других 0); `sh` — выстрелы |
| События | `server.gd` `_send_to` → `game.gd` `events_for` | 🖥 → 📱 `ev`, канал 0 | раз в 0.25 с — игроки рядом (себе `player_data`, другим `player_public`); по готовности — `tc` (изменённые клетки: двери), `fx` (эффекты: ранение, выстрел), `m` (сообщения этому игроку) |
| Приём | `game_screen.gd` `_handle_net` → `game.gd` `apply_state`, `apply_events` | 📱 | своя позиция не перезаписывается, кроме отката от сервера (`force_seq`) |

## 4. Сохранение персонажей

| Что | Где | Когда | Кто пишет |
|---|---|---|---|
| Имя, ID, пол | ☁️ `characters` | один раз при создании (изменить через API нельзя — политик `UPDATE` нет) | 📱 `account.gd` `create_character` |
| Вся карточка `Player` (позиция, здоровье, голод, жажда, выносливость, деньги `mo`, счёт `bk`, вещи `inv`, в руке `eq`, одежда `wr`, внешность `lk`, имя `nm`) | 🖥 `server_world.json` → поле `p` (`game.gd` `player_data`) | раз в 60 с, при выходе любого игрока, при остановке сервера | 🖥 `server.gd` `save_world` (временный файл → проверка длины → копия старого в `.bak` → замена) |
| Связь аккаунт → ID | 🖥 `server_world.json` → `uids` (`sb:<user_id>` и старые id телефонов) | там же | 🖥 |
| Офлайн-персонаж | 📱 `user://save.json` (`saves.gd`) | раз в 60 с, при паузе и выходе | 📱; к серверу и аккаунту не относится |

Загрузка: 🖥 `server.gd` `_load_world` → `valid_save` → `load_data` → `migrate` (сохранения v1–v3 переводятся;
при ошибке основного файла берётся `.bak`). Деньги и вещи в Supabase **не хранятся и не передаются**.

## 5. Деньги, предметы и другие игровые данные

**Механизмов передачи денег и предметов между игроками нет.** Нет торговли, передачи, магазинов, зарплаты,
выпадения вещей при нокауте, подбора вещей с земли, банковских операций.

Что есть на самом деле:

| Данные | Откуда берутся | Как меняются | Кто видит |
|---|---|---|---|
| Наличные `money` | 🖥 `START_MONEY` = 500 при создании карточки | ничем (кода изменения нет) | только сам игрок: `ev.p` (`player_data` → `mo`) |
| Счёт `bank` | 🖥 0 при создании | ничем | только сам игрок (`bk`) |
| Вещи `inv` | 🖥 стартовые (вода, чипсы) | `_use` (съесть, выпить, лечиться), выбросить (вещь исчезает), `_wear`/`_unwear` (вещь ↔ одежда), выстрел тратит патрон | только сам игрок (`inv`) |
| Одежда `wear`, внешность `look`, в руке `eq`, имя | 🖥 | надеть/снять, пол из Supabase | все рядом (`player_public`) — это видно в игре |
| Здоровье, голод, жажда, выносливость | 🖥 | `_finish_player`, `hit_player`, `_use` | `hp` и `stamina` — сам игрок (`st`), полностью — сам игрок (`ev.p`); другие — только «без сознания» |

Клиент деньги и вещи не меняет: он присылает только `act`, решение принимает сервер.

| Телефон: пакет | `launcher.gd` `_next` → загрузка в `.part` → `_sha256` | 📦 → 📱 `user://pck/`, учёт в `state.json` | sha256 сверяется с манифестом |
| Телефон: запуск | `launcher.gd` `_launch` → `ProjectSettings.load_resource_pack` | 📱 | `Engine meta`: `pack_build`, `server_host`, `server_port`, `latest_build`, `start_mode` |

| Сервер | `server/update.sh` (таймер раз в 2 мин, `setup.sh`) | 📦 → 🖥 HTTPS (`curl`) | сравнение `build`; sha256 архива против манифеста; остановка → замена → запуск службы `umwelt-server` (пользователь `umwelt`) |
| Совместимость | `server.gd` (`hello`) | 🖥 → 📱 `bye` | клиент другой сборки не впускается; если клиент новее — «сервер обновляется, зайди через пару минут» |

## 8. Потенциальные утечки, дублирование, небезопасная передача

Отмечено то, что видно в коде и в базе. «Предположение» — не проверено опытом.

### 8.1. Небезопасная передача

| # | Что | Где | Почему важно |
|---|---|---|---|
| Н1 | **ENet без шифрования**: токен доступа Supabase в `hello`, id телефона (`legacy`/`uid`), свои деньги, вещи, здоровье в `ev`, все позиции | `game_screen.gd` `_on_connected`, `net.gd`, `game.gd` `events_for` | перехват в той же сети (общий Wi-Fi) даёт токен на час: им можно войти на игровой сервер под этим игроком и читать его строку в `characters`. Известно (руководство, раздел 8): к монетизации — DTLS |
| Н2 | Пароль тестового бота открытым текстом в публичном workflow | `.github/workflows/auth-test.yml` | BF-026 |
| Н3 | Обновления проверяются sha256 **из того же манифеста**, без подписи | `launcher.gd` `_next`, `server/update.sh` | защищает от битой загрузки, не от подмены релиза. Вся цепочка доверия — аккаунт GitHub и HTTPS. APK дополнительно проверяет Android (подпись того же ключа) |
| Н4 | Адрес игрового сервера телефон берёт из манифеста | `launcher.gd` `_launch` → `boot.gd` | при подмене релиза телефоны подключатся к чужому серверу и отдадут ему токен (Н1). Та же цепочка доверия, что Н3 |
| Н5 | Сервер принимает свою позицию от телефона | `game.gd` `remote_input` | доверие ограничено запасом хода и проверкой пути (стены, двери, объекты); в этих пределах телефон решает сам |
| Н6 | Размер сообщений канала 0 от клиента кодом не ограничен (у канала 1 — 4096 байт) | `net.gd` `_recv_rel` | Предположение: можно нагрузить сервер большими `act`. Число `act` ограничено (30 за кадр), размер — нет |

### 8.2. Возможные утечки

| # | Что | Где | Подробно |
|---|---|---|---|
| У1 | **Выстрелы видны всем на карте**: `st.sh` отправляется каждому без учёта расстояния | `game.gd` `state_for` | координаты стрелка и попадания доступны игрокам в другом конце города (в игре они не видны, но лежат в пакете) |
| У2 | Эффекты `fx` (ранение — с ID раненого, выстрел — с ID стрелка) без учёта расстояния | `game.gd` `events_for`, `add_fx` | то же, что У1. Сейчас из-за BF-027 их получает только один игрок за кадр |

Проверено, что **не утекает**: чужие деньги, вещи, здоровье — `player_public` их не содержит, автотест
«Приватность: чужие деньги, вещи и ключи аккаунтов не уходят другим игрокам»; `uids` не уходит никому;

### 8.4. Найденная ошибка

**BF-027** — изменения клеток (`tc`: двери) и эффекты (`fx`) получает **только первый игрок**, для которого сервер
собирает события в этом кадре: `events_for` очищает `world.dirty_tiles` и `fx_net` сразу после первого игрока.
Проверено скриптом: дверь открыл игрок A — `tc` получил A, игрок B — нет. Остальные видят дверь в старом
положении до перезахода. Подробно — `docs/BUGFIX_LOG.md`, BF-027. Не исправлено (задание — только описание).
