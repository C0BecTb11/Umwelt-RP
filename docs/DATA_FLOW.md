# Umwelt RP — движение данных (DATA_FLOW)

Как данные ходят между тремя частями: **телефон** (Android: лаунчер + игра), **игровой сервер** (Hetzner,
`server_only/server.gd`) и **Supabase** (аккаунты). Плюс **GitHub Releases** — откуда приходят обновления.
Составлено по коду (проверено 2026-11-04, после версии 0.19) и по самой базе (`docs/SUPABASE_MAP.md`).
Описано только то, что есть в коде. Чего нет — так и написано.

Обозначения: 📱 телефон, 🖥 игровой сервер, ☁️ Supabase, 📦 GitHub Releases.
Каналы: **HTTPS** — шифрованный; **ENet** — UDP-порт 7777, **с 0.24 зашифрован DTLS**, с 0.27 телефон сверяет
сертификат сервера с вшитым в игру (`Net.SERVER_CERT`) — от подслушивания и от подмены сервера посередине; BF-038): канал 0 — надёжный RPC
(`Net.send` → `_recv_rel`), канал 1 — надёжный, сырые байты (`Net.send_fast` → `_on_bytes`, от клиента не больше
4096 байт).

## 0. Общая схема

```
                 HTTPS (вход, токен, персонаж)              HTTPS (проверка токена, имя/ID/пол)
   📱 account.gd ───────────────────────────────► ☁️ Supabase ◄──────────────────────────── 🖥 server.gd
        │  (токен доступа)                          ▲                                           ▲
        │                                           │ HTTPS: черновик карты (только админ)      │
        │                                   📱 map_editor.gd                                    │
        ▼                                                                                       │
   📱 game_screen.gd ═══════════ ENet UDP 7777, DTLS (с 0.24) ══════════════════════════════════╝
        hello(токен) → ; ← init(мир) ; in(ввод+позиция) 20/с → ; act(действия) → ; ← st 20/с ; ← ev

   📦 GitHub Releases «latest»: manifest.json, game.pck, umwelt-server.zip, umwelt.apk
        ├─ HTTPS → 📱 launcher.gd (пакет игры, адрес сервера)      ├─ HTTPS → 🖥 server/update.sh (сборка сервера)
        └─ HTTPS → 📱 game_screen.gd (напоминание об обновлении)
```

Где что **хранится** (единственный источник правды выделен):

| Данные | Где хранится | Копии |
|---|---|---|
| Аккаунт (почта, пароль) | **☁️ `auth.users`** | 📱 `user://account.cfg`: почта и refresh-токен (пароль не хранится) |
| Имя, постоянный ID, пол | **☁️ `public.characters`** | 🖥 `Player.name`, `Player.id`, `Player.look.g` в файле мира; 📱 в памяти |
| Деньги, счёт, вещи, одежда, здоровье, голод, позиция, уровень, опыт | **🖥 файл мира `server_world.json`** | 🖥 `server_world.bak.json` и часовые; с 0.54 ☁️ `world_backups` — сжатая копия раз в час, 7 дней; 📱 только в памяти (свои — полностью) |
| Кто какой игрок (`uids`: ключ аккаунта → ID) | **🖥 файл мира** | — (никому не отправляется) |
| Карта | **репозиторий `maps/city.json`** → 📦 game.pck и сборка сервера | 🖥 открытые двери — в файле мира; 📱 карта от сервера в памяти |
| Офлайн-мир («Офлайн-тест») | **📱 `user://save.json`** | `save.bak.json`; с сервером не связан |
| Черновик карты | 📱 `user://map_draft.json` | ☁️ `map_drafts` (после «Отправить») |

## 1. Регистрация и авторизация

Всё — 📱 ↔ ☁️ по HTTPS, игровой сервер не участвует.

| Шаг | Файл, функция | Откуда → куда | Данные |
|---|---|---|---|
| Кнопка «Играть» | `launcher.gd` `_launch("server")` → `main.gd` `_start_from_launcher` → `_play_server` | 📱 | `Engine meta start_mode = "server"` |
| Уже есть сессия | `main.gd` `_play_server` → `account.gd` `refresh()` | 📱 → ☁️ `POST /auth/v1/token?grant_type=refresh_token` | refresh-токен → новый токен доступа (живёт час), refresh-токен, `user.id`, почта |
| Вход | `main.gd` `_show_login` → `account.gd` `sign_in()` | 📱 → ☁️ `POST /auth/v1/token?grant_type=password` | почта, пароль |
| Регистрация | `account.gd` `sign_up()` | 📱 → ☁️ `POST /auth/v1/signup` | почта, пароль; если в Supabase включено подтверждение почты — сессии нет, игрок видит «отправили письмо» |
| Сохранение сессии | `account.gd` `_take_session()` → `_save()` | 📱 → `user://account.cfg` | почта, refresh-токен (токен доступа — только в памяти) |
| Есть ли персонаж | `main.gd` `_after_login` → `account.gd` `load_character()` | 📱 → ☁️ `GET /rest/v1/characters?select=id,name&user_id=eq.<свой>` | ответ: `id`, `name` (RLS отдаёт только свою строку) |
| Создание персонажа | `main.gd` `_show_create_character` → `account.gd` `valid_name()`, `create_character()` | 📱 → ☁️ `POST /rest/v1/characters` | `user_id`, `name`, `gender`; `id` база выдаёт сама; ошибки `23505` (имя занято), `23514` (формат) |
| Админ ли | `main.gd` `_after_login` → `account.gd` `check_admin()` | 📱 → ☁️ `POST /rest/v1/rpc/is_admin` → `user://editor.cfg` | `true/false`; только для кнопки редактора карты |
| Регистрация: согласие | `main.gd` `_show_login(register)` | 📱 | с 0.31 под кнопкой — «есть 16 лет и согласен с политикой» и кнопка «Политика конфиденциальности» → `OS.shell_open(AccountApi.PRIVACY_URL)` (https://c0bectb11.github.io/Umwelt-RP/privacy.html). Пароль при регистрации — от 8 символов (`MIN_PASSWORD`) |
| Экран «Аккаунт» | меню игры → «Аккаунт» (`hud.gd`, `screen.next = "account"`) → `main.gd` `_on_exit` → `_show_account` | 📱 | с 0.31: соединение с игровым сервером закрывается; почта и имя персонажа — из памяти `account.gd` |
| Выход из аккаунта | `main.gd` `_show_account` → `account.gd` `logout()` | 📱 → ☁️ `POST /auth/v1/logout?scope=local` | с 0.31 — кнопка «Выйти из аккаунта на этом телефоне»; затем `sign_out` стирает токены в `account.cfg`. `sign_out` один — когда сессия уже недействительна |
| Удаление аккаунта | `main.gd` `_show_delete_account` (слово УДАЛИТЬ) → `account.gd` `refresh()`, `delete_account()` | 📱 → ☁️ `POST /rest/v1/rpc/delete_my_account` (свежий токен) | с 0.31 (BF-044): база удаляет пользователя, каскадом — персонажа, права, черновики, сессии; триггер пишет `sha256(id)` в `account_deletions`. Телефон стирает почту и токены из `account.cfg` |
| Персонаж удалённого аккаунта | `server.gd` `_sync_deleted` (через 2 с после запуска, потом раз в 300 с; не в `--noauth`) → `drop_deleted` | 🖥 → ☁️ `POST /rest/v1/rpc/deleted_accounts` (только publishable-ключ, роль `anon`) | ответ — до 5000 отпечатков `h`; у кого `sha256(id)` совпал с ключом `sb:<id>` — ключ и карточка удаляются из мира, если он в игре — `bye` «Аккаунт удалён» и отключение, мир сохраняется. В часовых копиях — до 24 ч |

Ключ API в игре — только publishable (`Boot.SUPABASE_KEY`). Все проверки прав — правилами базы (RLS).

## 2. Подключение к игровому серверу

| Шаг | Файл, функция | Откуда → куда | Данные |
|---|---|---|---|
| Адрес сервера | `launcher.gd` `_launch` → Engine meta `server_host`/`server_port` → `boot.gd` `host()`/`port()` | 📦 manifest → 📱 | `server.host`, `server.port` из манифеста (по умолчанию в `boot.gd` — 2.31.45.237:7777) |
| Соединение | `main.gd` `_connect_game` → `net.gd` `join()` → `host.dtls_client_setup(TLS_NAME, client_tls(ip))` | 📱 → 🖥 ENet + DTLS | рукопожатие шифрования; с 0.27 сервер должен предъявить сертификат `Net.SERVER_CERT` (кроме 127.0.0.1 — тесты), иначе соединения нет; сервер — `Net.serve(…, Net.server_tls("user://dtls"))`, ключ `dtls.key`/`dtls.crt` создаётся при первом запуске сервера и лежит в его папке данных. Нешифрованный клиент не подключается |
| «Привет» | `game_screen.gd` `_on_connected` | 📱 → 🖥 `hello`, канал 0 | `token` (токен доступа Supabase), `uid` (`Profile.uid`, случайный id телефона — с 0.31 только если токена нет, то есть для `--noauth`; с аккаунтом — пустая строка), `nick` (`Profile.nick`), `build`. До 0.28 ещё `legacy` (то же значение) |
| Проверка сборки | `server.gd` `_handle_net` (`hello`) | 🖥 → 📱 `bye` | при несовпадении `build` — отказ с причиной |
| Проверка токена | `server.gd` `_verify` → `_sb("/auth/v1/user")` | 🖥 → ☁️ HTTPS | заголовки: publishable-ключ + **токен игрока**; ответ: `user.id` |
| Персонаж | `server.gd` `_verify` → `_sb("/rest/v1/characters?select=id,name,gender,created_at&user_id=eq.…")` | 🖥 → ☁️ HTTPS, тем же токеном игрока | `id`, `name`, `gender`; с 0.52 — `created_at` → `GameState.reg_from_iso` → дата регистрации «ГГГГ-ММ-ДД» по МСК в карточке игрока (`reg`, для «Статистики»; без аккаунта — дата первого входа) |
| Вход в мир | `server.gd` `_enter` → `game.gd` `join_player(key, name, id, gender)` | 🖥 | ключ `sb:<user_id>` → `uids`; имя и пол перезаписываются из Supabase при каждом входе |
| Старый персонаж телефона | `server.gd` `drop_phone_chars` (при запуске без `--noauth`) | 🖥 | с 0.28 к аккаунту не переходит: ключи `uids` не вида `sb:…` и их карточки удаляются (BF-042); до 0.28 — переходил по присланному `legacy` |
| Второе устройство | `server.gd` `_enter` | 🖥 → старое 📱 `bye` + отключение | «В этот аккаунт вошли с другого устройства» |
| Мир для клиента | `server.gd` `_enter` → `game.gd` `to_data_for(pid, false)` | 🖥 → 📱 `init`, канал 0 | `pid`, `seed`, `mapz` + `mapn` (с 0.34: карта — `var_to_bytes` + zstd; с 0.38 в ней и дороги-линии `lines`, сервер держит готовую копию и пересобирает при смене дверей; телефон — `GameState.unpack_map`, испорченная — отключение с причиной, BF-051), `world`: `time`, (до 0.34 — `map`: ряды клеток с дверями, объекты, точка появления), игроки в радиусе `SEE_R` = 20 клеток и не под крышей чужого здания (`sees`) (с 0.26; до — квадрат ±40, BF-040): **себе — `player_data`** (всё), **другим — `player_public`**; `uids` не отправляются |
| Приём мира | `game_screen.gd` `_handle_net` (`init`) → `GameState.load_data` (`is_replica = true`) | 📱 | карта из сообщения, не из своего файла |
| Объявление | `server.gd` `_enter` → `game.gd` `msg` | 🖥 → остальным 📱 в `ev.m` | «John_Miller (5) в городе» — **всем игрокам**, независимо от расстояния |
| Таймауты | `server.gd` `_handle_net` | 🖥 | без «привета» 5 с (`HELLO_WAIT`, с 0.22; 25 с, если идёт проверка в Supabase) — отключение. Токен неверного формата (`valid_token`: 20–4096 символов, только `A-Za-z0-9._-`) отклоняется без запроса в Supabase |
| Выход | `net.gd` `_on_peer_disconnected` → `server.gd` (`disconnect`) → `game.gd` `leave_player` → `save_world()` | 🖥 | персонаж остаётся в мире с `connected = false` |
| Обрыв связи | `game_screen.gd`: `disconnect` от ENet, 6 с без снимков `st` (`SILENCE_MS`) или 15 с без входа → `lost`, `can_retry` | 📱 | с 0.33 (BF-047). «До свидания» (`bye`) с причиной не повторяется, кроме «Сервер перезапускается» |
| Переподключение | `main.gd` `_retry_tick` → `account.gd` `refresh()` (новый токен) → `net.gd` `join(last_ip, last_port)` → новый `GameScreen` | 📱 → ☁️ HTTPS, 📱 → 🖥 ENet + DTLS | до 5 попыток через 3 с; дальше — тот же путь, что при входе (`hello` с новым токеном → `init`). Если старое подключение ещё «висит» на сервере — сервер закрывает его как «вход с другого устройства» |

Режим `--noauth` (только локальные тесты): вход по `uid` и `nick` из «привета», Supabase не спрашивается.

## 3. Игровые действия

| Что | Файл, функция | Откуда → куда | Данные и проверки |
|---|---|---|---|
| Движение | `game_screen.gd` `_process` (раз в 50 мс) | 📱 → 🖥 `in`, канал 1 | `ts`, `mx`/`my` (джойстик), `run`, **`x`/`y` — позиция, посчитанная телефоном**, `fx`/`fy`, `fs`. С 0.20 пакет, где хоть одно из чисел не конечное или не число, отбрасывается целиком (`GameState.net_num`) |
| Проверка движения | `game.gd` `remote_input` → `_path_free`, `_segment_free` | 🖥 | запас хода (`move_budget`: с 0.21 — по `max_speed`: бег 3.9 клетки/с, без выносливости шаг 2.3, усталость ×0.8, перегруз ×0.6; запас ×1.25), путь без стен, дверей и объектов; иначе `push_player` — откат (`force_seq` + 1). Бег и трата выносливости — по пройденному пути за 0.5 с (`win_d`/`win_t`), а не по флагам `run`/`mx` из пакета |
| Действия | `hud.gd` → `game_screen.gd` `act()` | 📱 → 🖥 `act`, канал 0 | `{"a": "attack"}`, `{"a": "interact", "c": клетка}`, `{"a": "use"/"drop"/"wear", "id": вещь}`, `{"a": "unwear", "slot": слот}`; с 0.52 — `{"a": "say", "text": текст}` (чат) |
| Приём действий | `server.gd` `_handle_net` (`act`) → `game.actions` | 🖥 | с 0.22: не больше 10 в секунду, разом до 15 (`Bucket`), лишние отбрасываются. Пакеты `in` — не больше 40 в секунду. Любое сообщение больше 8 КБ (`too_big`) — отключение |
| Проверка и выполнение | `game.gd` `update` → `_do_action` → `valid_action` → `_perform` (`_attack`, `_interact` + `near_cell`, `_use`, `_wear`, `_unwear`, выбросить) | 🖥 | типы полей, существование вещи (`Items.DEFS`), наличие у игрока, расстояние до двери, «жив» |
| Предсказание удара | `game_screen.gd` `act` → `game.gd` `predict_attack` | 📱 | только анимация; урон считает сервер |
| Лёгкий снимок | `server.gd` `_send_to` (раз в 50 мс) → `game.gd` `state_for` (с 0.34 видимых ищет сетка районов `index_players`/`_visible_entries` — те же игроки, что `sees`, BF-049) | 🖥 → 📱 `st`, канал 1 | `time`, `ts`; на каждого игрока в радиусе `SEE_R` = 20 клеток и не под крышей чужого здания (`sees`) 10 чисел: `id, x, y, fx, fy, удар, присед, force_seq, hp, stamina` (**hp и stamina — только свои**, у других 0); `sh` — выстрелы рядом (с 0.21: начало или конец в радиусе `VIEW_R`) |
| События | `server.gd` `_send_to` → `game.gd` `events_for` | 🖥 → 📱 `ev`, канал 0 | раз в 0.25 с, в кадре снимка — себе `player_data`; другим в радиусе `SEE_R` = 20 и не под крышей чужого здания — `player_public` **только тем, кого телефон ещё не знает или у кого изменились внешность, одежда, предмет в руке, имя, «без сознания»** (с 0.34, BF-050: подпись `pub_sig`, что кому отправлено — `sent_pub`, сброс при входе и выходе получателя; позиция идёт снимками). Между полными — только если есть эффекты, двери или сообщения; по готовности — `tc` (изменённые клетки: двери — всем; до 0.21 только одному, BF-027), `fx` (эффекты: ранение, выстрел — с 0.21 только в радиусе `VIEW_R`), `m` (сообщения этому игроку — плашки, в том числе PayDay), с 0.52 `c` (чат этому игроку; с 0.53 каждая запись — `[id сказавшего, текст, строка чата]`: строка — в чат, текст — облачком над головой). Общие списки очищает сервер после рассылки всем |
| Чат (с 0.52) | `hud.gd` `_send_chat` → `act` `say` → `game.gd` `_say` (`clean_chat`) → `chat[pid]` → `events_for` (`c`) → `hud.gd` `on_chat` (строка — `add_chat`, облачко над головой — `bubbles`, 0.53) | 📱 → 🖥 → 📱 рядом | строка «Имя_Фамилия (ID) говорит: текст» — всем в игре ближе `CHAT_R` = 20 м и самому говорящему. Текст без управляющих символов, до `CHAT_MAX` = 120 символов, не чаще раза в `CHAT_GAP` = 1 с (иначе плашка «Не так быстро»); `act` и так ограничен 10/с. Рассылка: строки живут до ближайшей рассылки; ушедшим не копятся. До 0.55 сервер чат не хранил; **с 0.55 каждое сообщение пишется в журнал действий** (ниже, «Журнал действий»). На телефоне — последние 40 строк в памяти |
| PayDay (с 0.52) | `game.gd` `update` → `_account_time`, `payday` | 🖥 (офлайн — 📱) → 📱 `ev.m` | в начале каждого часа МСК (`payday_hour`). Кто в игре и отыграл за час ≥ 20 мин без АФК — `bank` += `payday_salary` (пока 0 — организаций нет) и +1 опыт (уровень — `exp_need`: 4, 6, 8…), плашки «PayDay! Зарплата $N…» и «Уровень, опыт»; иначе — «зарплата и опыт не начислены» и «не отыграли минимум 20 минут». АФК — больше `AFK_AFTER` = 120 с без движения, действий и чата (пустое сообщение АФК не снимает — 0.53, BF-070). С 0.53 (BF-069) PayDay — только когда номер часа стал **больше** прошлого: откат часов сервера назад его не повторяет; скачок назад больше часа — без PayDay; вперёд на несколько часов — один PayDay. Опыт, уровень и отыгранное время считает только сервер; от телефона он принимает лишь движение (`in`) и действия из списка (`valid_action`) — поля уровня/опыта/времени в них не читаются |
| Приём | `game_screen.gd` `_handle_net` → `game.gd` `apply_state`, `apply_events` | 📱 | своя позиция не перезаписывается, кроме отката от сервера (`force_seq`) |

## 4. Сохранение персонажей

| Что | Где | Когда | Кто пишет |
|---|---|---|---|
| Имя, ID, пол | ☁️ `characters` | один раз при создании (изменить через API нельзя — политик `UPDATE` нет) | 📱 `account.gd` `create_character` |

### 8.4. Найденная ошибка

**BF-027** — изменения клеток (`tc`: двери) и эффекты (`fx`) получал **только первый игрок**, для которого сервер
собирал события в этом кадре: `events_for` очищал общие списки сразу после первого игрока. **Исправлено в 0.21**:
`events_for` общее не меняет, очищает сервер после рассылки всем. Подробно — `docs/BUGFIX_LOG.md`, BF-027.
