# Umwelt RP — руководство проекта

Мобильная РП-игра (Android) в духе SAMP RP. Сеттинг: Америка, 1990-е. Движок: Godot 4.4.1 (GL Compatibility).
Документ обязателен к прочтению перед любой работой и **обновляется вместе с кодом**: поменял правило, механику или
способ сборки — поправь этот файл в том же коммите.

---

## 1. Как всё устроено

```
 Телефон                                   GitHub                         Hetzner (2.31.45.237)
┌──────────────────────┐   HTTPS   ┌──────────────────────────┐  раз в   ┌──────────────────────────┐
│ umwelt.apk = лаунчер │ ◄──────── │ Releases → «latest»       │ 2 мин    │ umwelt-update (таймер)   │
│ + встроенная игра    │  manifest │  manifest.json            │ ───────► │ скачивает сервер, сверяет│
│ скачивает game.pck,  │  game.pck │  game.pck                 │          │ SHA-256, перезапускает   │
│ проверяет SHA-256,   │           │  umwelt-server.zip        │          │                          │
│ подключает и играет  │           │  umwelt.apk               │          │ umwelt-server (Godot     │
└─────────┬────────────┘           └────────────▲─────────────┘          │ без графики), порт 7777  │
          │  ENet UDP 7777                       │ пуш в main → сборка   └────────────▲─────────────┘
          └──────────────────────────────────────┼────────────────────────────────────┘
                                                 │
                                       .github/workflows/build.yml
```

- **Вся игровая логика — на сервере** (`scripts/server_only/server.gd` + `scripts/game.gd`). Телефон присылает ввод (куда идёт)
  и действия («ударить», «взять»), сервер всё проверяет и рассылает результат.
- Свой персонаж двигается на телефоне сразу (предсказание), сервер принимает позицию, только если она честная
  (скорость, стены, двери). Нечестную откатывает (`push_player`, номер отката `force_seq`).
- Чужих игроков телефон рисует с небольшой задержкой между двумя пакетами (`NetClock`, `sample_snaps`) —
  поэтому без рывков даже на плохом интернете.
- **Обновления без переустановки**: APK — это лаунчер со встроенной игрой. При запуске он сверяется с
  `manifest.json` в релизе «latest» и докачивает `game.pck` (новая версия кода и ресурсов игры).
- **Сервер обновляется сам**: таймер на Hetzner раз в 2 минуты смотрит манифест и при новой сборке ставит её.

## 2. Структура репозитория

Подробная карта: дерево файлов, классы, кто кого вызывает, сетевые сообщения, критичные файлы, неиспользуемый
код — **`docs/PROJECT_MAP.md`**. Ниже — кратко.

| `scripts/server_only/nettest.gd` | Сетевой тест: сервер + несколько клиентов |
| `server/setup.sh`, `update.sh` | Установка и автообновление сервера на Hetzner |

| `NEWS.md` | Первая строка показывается в лаунчере как новость |

## 3. Как выходит обновление

1. Изменения попадают в ветку `main`.
2. GitHub Actions (`build.yml`): автотесты → `game.pck` → сервер → APK (если нужно) → `manifest.json` и его
   подпись `manifest.sig` (ключом подписи APK; с 0.25 лаунчер без верной подписи обновление не ставит) → релиз «latest».
   **Если хоть один тест упал — релиза не будет.** Лог упавшей сборки — в ветке `buildlog`.
3. Игроки: при следующем запуске лаунчер скачает обновление.
4. Сервер: в течение ~2 минут сам скачает и перезапустится (игроков на эти секунды выкинет — это нормально).
   Если телефон успел обновиться раньше сервера, игрок увидит «Сервер обновляется — зайди через пару минут».

### Когда нужен новый APK
Определяется **автоматически** (по «отпечатку»): изменился `launcher/`, `project.godot`, `export_presets.cfg`,
версия Godot или **появился/пропал/переименован `class_name`**. Тогда собирается новый APK, и лаунчер у игроков
покажет «Скачать новую версию приложения». Новый APK ставится поверх старого — персонаж и настройки сохраняются.
Совет: новые классы без нужды не делать (`class_name`), вспомогательные скрипты подключать через `preload`.

**Размер APK.** Почти весь APK — движок Godot (`libgodot_android.so`, ~25 МБ в сжатом виде) по копии на каждый тип
процессора; сама игра — ~4 МБ. С 0.32 собираются `arm64-v8a` (64-бит) и `armeabi-v7a` (старые 32-битные телефоны —
решение владельца оставить); `x86`, `x86_64` (эмуляторы, Chromebook) — нет. APK 0.31: 82 МБ (три копии движка).

### Версия игры
Версия = `0.<номер сборки>` (номер запуска CI, он же `Version.BUILD`). Видна в углу лаунчера и в меню паузы.
Сервер пускает только клиента той же сборки.

### Версии и откат
- Каждый коммит подписан так: **«0.N: что сделано»** — N совпадает с версией, которую увидят игроки.
  Правки только руководства — «Руководство: … (без выпуска) [skip ci]»: сборка не запускается, версия не тратится.
- CI пишет версию, номер коммита и описание в релиз «latest» (GitHub → Releases). Метки `v0.N` сборка ставить
  не может (GitHub запрещает её токену трогать коммиты с изменёнными workflow), поэтому версия → коммит — в таблице.
- **Откатиться**: сказать Claude «откати на 0.N». Он делает `git revert` всех коммитов после коммита 0.N — это новая
  версия с прежним кодом (история не стирается, к любой версии можно вернуться снова). Сервер и телефоны
  обновятся сами, как при обычном выпуске.
- Осторожно с сохранениями: если после 0.N поднимали `SAVE_VERSION` (0.11 → v2, 0.17 → v3), старый код новый мир
  не прочтёт как надо. Перед таким откатом — копия `server_world.json` на сервере.

### Напоминания об обновлении
- Лаунчер при старте сам скачивает обновление; если нужно новое приложение — показывает кнопку «Скачать новую версию».
- В игре раз в 3 минуты проверяется манифест; если вышла сборка новее — сообщение и постоянная плашка под часами
  «Доступно обновление 0.N — закрой и открой игру». После выхода в лаунчер он тоже это напомнит.
- Системные уведомления Android (в шторке) пока не делаем — для них нужен Android-плагин и новый APK.

## 4. Правила кода (обязательные)

1. **Сервер решает всё.** Любое новое действие игрока:
   - добавить в `GameState.valid_action()` с проверкой типов полей;
   - в обработчике проверить расстояние (`near_cell`), наличие предмета, состояние (жив, не лезет в окно);
   - написать автотест «нельзя сделать нечестно» в `audit_test.gd`.
2. **Никаких автозагрузок (autoload).** Сеть — `Net.I`, профиль — `Profile`. Автозагрузки не обновляются пакетом.
3. **Лаунчер не трогает классы игры** (`Version`, `Boot`, `Net` и т.д.) — иначе после подключения пакета
   в памяти останется старая версия. Данные в игру — только через `Engine.set_meta`.
4. **Новое поле у игрока или мира** → добавить в `player_data()`/`player_from()` (или `to_data()`/`load_data()`)
   со значением по умолчанию через `.get(ключ, умолчание)`. Если меняется смысл старых данных — поднять
   `SAVE_VERSION` и дописать шаг в `migrate()`. Старые сохранения сервера должны загружаться всегда.
5. **Приватность.** Другим игрокам уходит только `player_public()` (имя, одежда, в руках, без сознания).
   Деньги, инвентарь, здоровье — только самому игроку. Карту аккаунтов `uids` не отправлять никому:
   uid — это ключ от персонажа.
6. **Позиции и ввод — канал 1, надёжный** (`Net.I.send_fast`). Не переводить на «ненадёжный»: ENet тогда
   выкидывает пакеты сериями по секунде (проверено замерами — друг «замирал» и прыгал).
7. **Каждый найденный баг** — сначала тест, который его ловит (должен упасть на старом коде), потом исправление.
8. **Серверное — только в `scripts/server_only/`.** Эта папка не попадает в APK и пакет игры (фильтр экспорта
   Android), сборка проверяет это сама и падает, если серверный код утёк. Сюда — вход/аккаунты, админка,
   античит, экономика, всё, что игроку видеть не нужно. Подключать только через `load("res://scripts/server_only/…")`,
   без `class_name`. Общие правила игры (движение, предметы) — в `game.gd`: они нужны и телефону.
9. **Никаких секретов в коде клиента.** В игре могут быть только публичные данные (адрес сервера, publishable-ключ
   Supabase). Пароли, сервисные ключи, токены — только на сервере (файлы вне репозитория) или в секретах GitHub.
   Всё, что лежит в APK, считаем прочитанным: его разбирают готовыми программами.
10. **Карточка игрока.** Всё, что принадлежит игроку (наличные `money`, банковский счёт `bank`, вещи,
   одежда, а дальше — машины, дома, работа, фракция, лицензии), — поле класса `GameState.Player` и
   сохраняется в `player_data()`. Отдельных словарей «игрок → что-то» в стороне не заводить. Если вещь живёт
   в мире (машина на улице, дом), у неё поле `owner` = **ID игрока**, а не имя и не uid.
   ID постоянный: для аккаунта это `characters.id` из Supabase, у игроков без аккаунта — от 1 000 000.
   В текстах для игроков имя пишется через `GameState.tag(p)` → `John_Miller (5)`.
11. Тексты для игрока — по-русски. Комментарии в коде — по-русски, коротко и по делу.
12. **Документация — часть исходного кода.** Документация является частью исходного кода проекта. ## 6. Сервер (Hetzner CPX02: 1 ядро, 1 ГБ, общий с sw-rpg)

**Установка (один раз, от root, в консоли Hetzner или Termius):**
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/C0BecTb11/Umwelt-RP/main/server/setup.sh)
```
Скрипт безопасно запускать повторно. sw-rpg он не трогает.

| Что | Где |
|---|---|
| Игровой сервер | `/srv/umwelt/server/` (пользователь `umwelt`, служба `umwelt-server`) |
| Мир и персонажи | `/srv/umwelt/data/godot/app_userdata/Umwelt RP/server_world.json` (+ `.bak.json` + часовые `server_world.h00…h23.json`) |
| Ключ шифрования канала | `/srv/umwelt/data/godot/app_userdata/Umwelt RP/dtls/` (`dtls.key` — секретный, `dtls.crt` — публичный, вшит в игру с 0.27), создаётся при первом запуске 0.24. **Не удалять** — раздел 8 |
| Автообновление | `/usr/local/bin/umwelt-update` (копия `server/update.sh`; сама не обновляется — раздел 8), таймер `umwelt-update.timer` (каждые 2 мин) |
| Остановка с сохранением | `/usr/local/bin/umwelt-stop` (`ExecStop` службы, из `setup.sh`) |
| Фаервол порта игры | `/etc/umwelt-firewall.nft`, служба `umwelt-firewall` (из `setup.sh`, если на сервере есть `nft`) |
| Порт | 7777/UDP. Если у сервера включён фаервол Hetzner (вкладка Firewalls) — добавить правило Inbound UDP 7777 |
| Лимит памяти | 450 МБ (`MemoryMax`), чтобы игра не задавила sw-rpg. Swap 1 ГБ создаётся, если его не было |

Полезные команды:
```bash
journalctl -u umwelt-server -f          # журнал (входы, выходы, онлайн, время кадра)
systemctl restart umwelt-server         # перезапуск
systemctl status umwelt-server
journalctl -u umwelt-update -n 20       # что делал автообновлятор
cp "/srv/umwelt/data/godot/app_userdata/Umwelt RP/server_world.json" ~/backup-$(date +%F).json   # бэкап мира
```
Мир сохраняется раз в 15 секунд, при каждом выходе игрока и при остановке службы: через временный файл, только
если текст читается обратно; прежний файл уходит в `.bak` (если он сам цел), раз в час — копия на этот час суток
(24 штуки). При загрузке: основной → `.bak` → часовые от свежей к старой. Остановка (`systemctl stop`, обновление,
перезагрузка): Godot сигнал остановки не ловит, поэтому служба запускает `/usr/local/bin/umwelt-stop` — он кладёт
файл `stop.request` в папку данных, сервер сохраняет мир и выходит сам (до 10 с ожидания; с 0.29, на боевом
сервере — с 2026-11-04, проверено по журналу, BF-029).

Защита от занятия мест (BF-043): с одного адреса — не больше 3 подключений, ещё не вошедших в мир (в игре), и не
больше 1000 пакетов в секунду на порт 7777 (фаервол `umwelt-firewall`, своя таблица nftables `umwelt_fw`;
посмотреть: `nft list table inet umwelt_fw`, сколько отброшено — в строках `counter`). Снять фаервол:
`systemctl disable --now umwelt-firewall`. Вернуть мир на несколько часов назад:
остановить службу, скопировать нужный `server_world.hЧЧ.json` поверх `server_world.json`, запустить.

## 6в. Время суток

- Время в игре — **реальное московское** (UTC+3): сервер каждый кадр берёт его из своих часов
  (`GameState.msk_time()`), телефоны получают его в снимках. На экране — дата и время: «2 ноября · 18:20». В офлайн-тесте —
  те же часы телефона. Демо-снимки ставят своё время (`real_clock = false`).
- Темно только ночью (`darkness()`): светло 06:00–21:00, сумерки 21:00–22:30, ночь 22:30–04:30, рассвет 04:30–06:00.
  Солнце идёт с 05:00 до 21:30; на закате желтеет только солнечный свет, общий свет не темнеет до сумерек.
- Ночью светлее, чем в Zomboid: видно улицы без фонарика (`night_a`, `night_c` в `world_view.gd`). Ночью горят фонари.
- **Тумана войны и фонарика нет** (убраны в 0.16 по решению владельца): весь город виден всегда, затемнения
  «невидимых» мест нет. Другие игроки (с 0.26) приходят телефону, только если они в 20 клетках (`SEE_R`; экран
  телефона — до ~17 клеток от игрока, остальное — запас, чтобы не «выскакивали» у края) **и** не под крышей
  чужого здания (`GameState.sees`, `building_at` — та же граница «внутри», что у телефона, чью крышу не рисовать).
  На экране это не видно — их и так закрывала крыша; но изменённый клиент больше не знает, кто где в домах.
  Выстрелы и эффекты — как прежде, в радиусе `VIEW_R` = 40.

## 6б. Персонажи и одежда

- **Модели**: Quaternius «Ultimate Modular Men / Women» (2022), лицензия **CC0** — можно в платной игре, указывать
  автора не обязательно (`assets/chars/LICENSE.txt`). Исходные архивы владелец скачивал с quaternius.com.
- **Как устроено**: `assets/chars/m_base.scn` и `f_base.scn` — скелет (62 кости) и анимации; `assets/chars/m|f/*.scn` —
  части: голова (причёска или головной убор), верх, низ, обувь, а также пистолет. Часть — меш, привязанный к тому же скелету, поэтому
  любая одежда сразу двигается со всеми анимациями. Своей «нарисованной кодом» одежды нет — **владелец решил: только
  модели из наборов или от художника.**
- **Анимации** (оставлены 13 из 24): Idle, Walk, Run, Punch_Right/Left, Kick_Right (добивание), Death (нокаут),
  HitRecieve, Sword_Slash (холодное оружие), Gun_Shoot, Idle_Gun_Pointing, Interact, Wave. Выбор — `CharModel.pose()`.
- **Внешность** — в карточке игрока `look`: `g` пол (`m`/`f`, из `characters.gender`), `h` причёска (список
  `Items.HEADS`), `sk` тон кожи 0..3. По умолчанию — из ID (`GameState.default_look`). Пол выбирается при создании
  персонажа; сменить — только админ в базе (`characters.gender`), применится при следующем входе.
- **Одежда** — `Items.DEFS`, у вещи `parts` = {пол: имя части}; нет части для пола — вещь этому полу не подходит.
  `also` — что вещь закрывает ещё (платье — и низ). Пустой слот показывает `Items.BARE`. Новым — `Items.START_WEAR`.
- **Добавить вещь из набора**: дописать часть в `PARTS` скрипта `docs/tools/extract_chars.gd` и запустить его в
  отдельном проекте с glTF (как — в начале скрипта); он кладёт `assets/chars/<пол>/<Имя>.scn`. Затем строка в
  `Items.DEFS` и иконка в `icons.gd`. Тест «у всех вещей и причёсок есть модели» не даст забыть файл.
- **Головной убор** (слот `head`: каска, шлем спецназа, шляпа фермера) — часть «голова» другого образа, на время
  заменяет причёску.
- **Цветные варианты**: материалы частей однотонные (без текстур), поэтому цвет меняется заменой материала по имени
  (`set_surface_override_material`). У вещи `tint` = {пол: имя материала}; варианты описаны в `Items.COLORS` и
  создаются сами (`hoodie_red`, `tshirt_navy`, `dress_black`…). Так же сделан тон кожи. Это **не своя одежда** —
  та же модель из набора другого цвета.
- **Что ещё есть в архивах и не взято** (не для 90-х): King, Spacesuit, SciFi, Medieval, Witch, Beach-ноги у женщин нет.
  Другие бесплатные (CC0) наборы на этот скелет не садятся: новый Quaternius (Universal Base Characters + Outfits Fantasy)
  — другой скелет и пока только фэнтези; OverScore Proxy (315 вещей, CC0) — только женская база, без скелета, файлы
  .blend (нужен Blender). Платные наборы (Synty и т.п.) — свой скелет, и **публиковать их в открытом репозитории
  нельзя**: перед покупкой сделать репозиторий закрытым.

## 6г. Карта и редактор карты

**Карта игры — файл `maps/city.json`.** Сервер и офлайн-тест берут город только из него; меняется он только
коммитом с выпуском (видно, что поменяли, можно откатить). Генератора города больше нет (удалён в 0.19).
- Формат: `w`, `h`, `spawn` (точка появления и «больница»), `rows` — по строке на ряд, символ на клетку,
  `props` — объекты `[id, x, y, поворот°]` по одному на строку, `lines` (с 0.38, только если есть) — дороги-линии
  `[вид, x0, y0, x1, y1, …]` по одной на строку.
- Символы (`GameWorld.MAP_CHARS`): `.` трава, `=` асфальт, `-` тротуар, `w` пол-доски, `t` пол-плитка, `#` стена,
  `D` дверь (закрыта), `d` дверь (открыта), `O` окно, `T` дерево, `F` холодильник, `C` стойка, `W` шкаф, `S` полка,
  `M` аптечка, `L` шкафчик, `R` стеллаж, `c`/`v` машина вдоль/поперёк, `x` её вторая клетка, `~` вода (с 0.40).
  `?` и `!` запрещены.
- Объекты — `scripts/props.gd`: id, название, круги столкновений `col` (сквозь объект не пройти — так же, как
  сквозь стену; проверяет и телефон, и сервер). Новый объект = запись в `DEFS` + модель в `build()` + в `ORDER`.
  id объекта, который уже стоит на карте, не переименовывать и не удалять — карта перестанет загружаться.
- Дома и крыши определяются сами по стенам и полу; направление дверей и окон — по соседним стенам.
- Сохранение мира хранит только, какие двери открыты. При новой карте: двери на тех же местах сохраняют
  состояние, игрок в новой стене или объекте переставляется рядом (или к точке появления).
- **Размер:** до **500×500** клеток (`GameWorld.MAX_SIDE`, с 0.35; 1 клетка ≈ 1 м: окно — до 1.85, дверь — 1.8).
  Карта уходит телефону при входе сжатой (с 0.34: 100×100 — ~2 КБ вместо 15), сервер держит сжатую копию и
  пересобирает её, только когда меняются двери. Чем больше карта, тем меньше игроков рядом и тем легче серверу.
- **Город 500×500 (замер 2026-11-06, нынешний город, уложенный 5×5: 1450 домов, 3050 объектов):** загрузка карты
  ~0.4 с (на машине Claude; телефон — медленнее), для входа сжато — единицы КБ. Вся графика города — 2500 кусков,
  ~19 млн вершин, +410 МБ памяти — телефону не по силам, поэтому с 0.35 телефон держит построенной только округу
  игрока: куски в радиусе `stream_r` = 4 (40 клеток, экран — до ~17), дальние освобождает (BF-052) — это не
  больше 121 куска, как весь нынешний город. Крыши всех домов (165 тыс. вершин) строятся сразу. Редактор при
  отдалении держит больше: `stream_r` до 10.
- **Сколько идти через город 500×500** (симуляция по прямой по пустому полю, правила движения игры): шагом
  (2.3 м/с) край → край 497 м — **3 мин 35 с**, угол → угол 703 м — **5 мин 05 с**. С зажатым бегом — почти так же
  (3:33 и 5:04): выносливости хватает на ~8 с бега (3.9 м/с), дальше шаг со штрафом ×0.8, пока она ниже 10. По
  настоящим улицам с обходом домов — дольше.

**Дороги-линии (с 0.38).** Кроме клеточных дорог (`=`), на карте есть дороги, нарисованные точками: игра сглаживает
точки в кривую (`GameWorld.line_path`, шаг ≤ 1 м) и строит по ней асфальт с разметкой. С 0.44 (BF-058) кривая —
прямые между точками, углы скруглены дугой (`line_corners`): желаемый радиус `LINE_TURN_R` (улица 10 м, трасса
25 м, мост 15 м), на коротких отрезках дуга меньше (отступ дуги — не больше половины отрезка, крайнего — целиком).
Кривая проходит через первую и последнюю точку, внутренние точки — вершины углов. До 0.44 был Катмулл-Ром: на
резко поставленных точках он давал петли и повороты радиусом 2–7 м — трасса наезжала сама на себя.
- Виды (`GameWorld.LINE_KINDS`): `street` — улица: асфальт 6 м, пунктир по оси, бордюр и тротуары по 2 м;
  `highway` — трасса: асфальт 12 м (4 полосы), двойная сплошная, прерывистые между полосами, сплошные по краям,
  обочины по 1.5 м. Ширины — `LINE_ROAD_HW`/`LINE_OUTER_HW`. До 2000 дорог, до 64 точек в каждой.
- По дорогам-линиям можно ходить везде (столкновений нет, клетки под ними не меняются). Асфальт лежит чуть выше
  травы и клеточной дороги (4–5 см, с 0.43; раньше 2 см), поэтому их можно соединять; клеточный тротуар, полы и дома выше — рисовать
  дорогу-линию поверх них нельзя (она уйдёт под них).
- Перекрёсток строится сам (с 0.43, BF-057): дорога — стопка «мазков» по одной кривой, каждый уже и выше
  предыдущего (`WorldMesh._stroke`): улица — тротуар 3 см → бордюр 3.5 см → асфальт 4 см; трасса — обочина
  3.75 см → асфальт 4 см (белые кромки — с 0.44 разметкой); разметка — 5.6 см. Асфальт любой дороги лежит
  выше любых тротуаров/обочин — закрывает их на перекрёстке, в петле и на крутом повороте. Мазок — прямоугольник
  на кусок по его нормали + клин-дуга на стыке с предыдущим куском, с нахлёстом 5 см (`LINE_OVERLAP`).
  Разметки нет на асфальте другой линии и на своём, если кусок дальше 25 м по пути (петля) — `on_line_road`
  с `s_self`. Камешки и травинки клеток под дорогой не рисуются (с запасом 0.6 м, BF-054).
- Перекрёстки с разметкой (с 0.44, BF-058): `GameWorld._find_junctions` находит пересечения осей (сетка 2 м,
  каждая пара кусков один раз) под углом больше ~20° (`JUNC_MIN_SIN`); стык конец-в-конец — не перекрёсток.
  Записи — `lines_junc` (по кускам графики) и `line_junc` (по линиям), длины линий — `line_len`. Рисует
  `WorldMesh._junction` в куске точки пересечения: на каждом подъезде каждой дороги — «зебра» поперёк неё вдоль
  края чужой дороги (от её асфальта + 0.5 м до её тротуара/обочины + 0.6 м) и стоп-линия на половине, что едет
  к перекрёстку (правостороннее движение), там, где снова начинается разметка; подъезд рисуется, только если
  дорога продолжается за стоп-линию; полоски — только целиком на асфальте своей дороги (`on_line`). Осевая,
  полосы и белые кромки рвутся внутри перекрёстка — ближе края чужой дороги + 1 м (`_junc_hide`), и только где
  чужая дорога есть: на Т-перекрёстке кромка по ту сторону — целая. Скорость: 300 линий по ~280 м с ~4800
  пересечениями — ~0.6 с вместо 0.1 с (ПК); обычная карта — десятки мс.
- Графика: кривая режется на куски ~1 м и раскладывается по кускам графики (`lines_chunk`, как `props_chunk`).
  Концы линии продлены на 0.3 м (с 0.41): у двух дорог, сходящихся под углом, на стыке нет щели с травой.

**Вода и мосты (с 0.40).** Вода — клетки `~` (кисть «Вода»). Берег не по клеткам, а плавный:
- Поле воды (`GameWorld.water_corner`): в каждом углу сетки — доля воды в 4 клетках вокруг; внутри клетки —
  билинейно (`bilerp`); вода — где поле больше 0.5 (`water_at`). По этому же полю и рисуется гладь с берегом
  (`WorldMesh._shore`: клетка у берега делится на 4×4, берег — стенка вниз), и решается, где не пройти
  (`circle_blocked` → `_water_blocks`: середина и 8 точек по краю круга). Что видно — то и не пройти (тест).
- Вода — от 2 клеток в ширину: одинокая клетка `~` (и полоса в 1 клетку) по полю водой не становится — это трава.
- На дорогу, тротуар, пол и дома вода не заходит: у угла рядом с не-травой поле не больше 0.5 — там берег
  прямой по краю клетки.
- Гладь — на 0.6 м ниже земли (`WATER_Y`). С 0.41 вид воды:
  - глубина: `GameWorld.water_dist` — клеток до суши (8 соседей, до 10), считается при загрузке и правке;
    цвет глади в каждой вершине — от мелкой (`SHALLOW_COL`, у берега) к глубокой (`DEEP_COL`), плавно;
  - берег — земляной откос (`WorldMesh._slope`, 0.45 м в воду) и полоска пены там, где он уходит под воду
    (`Mesher.M_FOAM`, «дышит» в шейдере). Направление откоса — наклон поля, сглаженный по углам сетки: у соседних
    клеток он общий, щелей нет;
  - шейдер: рябь двумя-тремя бегущими волнами, нормаль наклоняется по ним (свет и тень движутся), блик солнца
    (`sun_dir` задаёт `world_view.gd`) и отсвет неба под углом. Ночью блика нет.
- **Мост** — дорога-линия вида `bridge` («Мост» в инструменте «Дорога»): асфальт 6 м и тротуары по 0.75 м. Над
  водой по нему можно ходить (`on_bridge`: весь круг на настиле, кроме 0.15 м у перил — `BRIDGE_RAIL`); где под
  краем вода — перила, бетонный край вниз и опоры раз в 8 м. Мост проводить через воду с заходом на берег.

**Материалы (с 0.37).** Город по-прежнему строится кодом из клеток (`world_mesh.gd`), но поверх цвета ложатся
текстуры из набора Quaternius «Downtown City MegaKit» (CC0, `assets/tex/LICENSE.txt`).
- Все текстуры — один файл `assets/tex/world_albedo.png`: слои 512×512 сверху вниз (импорт «2D Array», сжатие
  для видеокарты; в пакете ~1.4 МБ). Собрать заново: `python3 docs/tools/build_textures.py путь/к/Textures`
  (папка `Textures` из архива набора; архив в репозиторий не кладём — нужен только для пересборки).
- Слой выбирает `Mesher.mat` (`M_BRICK`, `M_CONCRETE`…; 0 — без текстуры): номер уходит в UV.x вершины. Развёртки
  нет — шейдер кладёт текстуру по мировым координатам на ту плоскость, к которой ближе нормаль.
- В шейдере у каждого слоя: метров на повтор (`SCALE`), средняя яркость (`MEAN`) и сила узора (`STRENGTH`).
  У бетона, асфальта, мрамора, черепицы и земли цвет задаёт по-прежнему цвет вершины, текстура — только узор
  (цвета домов и крыш остались). Кирпич и комнаты за окном — со своим цветом, цвет вершины лишь подкрашивает.
  Текстура переводится в линейный цвет в самом шейдере (`to_linear`): в режиме совместимости телефона массив
  с пометкой `source_color` оставался в sRGB — город выходил в 2–3 раза светлее.
- Стены: снаружи — кирпич (с оттенком) или штукатурка цвета дома, внутрь комнаты — штукатурка
  (`Mesher.face_mat`/`face_col` — материал по граням коробки). Пока вид дома выбирается по его номеру
  (`WorldMesh.wall_mat`, ~40% кирпичных); выбор в редакторе — следующий шаг.
- За окном снаружи — картинка комнаты (светлая или тёмная, светлые ночью светятся); изнутри дома окно — обычное
  стекло. Трава — зелёный цвет с узором земли. Дерево полов, мебель, объекты, машины — без текстур, как было.
- Новый слой: дописать в `LAYERS` скрипта, пересобрать, в `.import` поднять `slices/vertical`, в шейдере
  удлинить `SCALE`/`MEAN`/`STRENGTH`, в `Mesher` — новый `M_…`. Тест `test_world_textures` сверяет число слоёв.

**Редактор (у владельца):** «Офлайн-тест» → пауза → «Редактор карты». Кнопка есть только у аккаунта-админа
(проверка `is_admin` при входе через «Играть», ответ хранится в `user://editor.cfg`).
- Два пальца — двигать и приближать. Инструменты: Рука, Кисть, Прямоуг. (заливка), Рамка (только края — стены
  дома), Объект (палитра + поворот), Выбор (тянуть, повернуть 45°/90°, копия, удалить), Спавн, Дорога (с 0.38).
  В палитре кисти — «Вода» (с 0.40), у «Дороги» — «Мост».
- «Дорога»: каждое касание — следующая точка (видна оранжевой меткой), дорога сразу строится. Внизу: «Улица» /
  «Трасса» / «Мост» (вид новой дороги, у рисуемой — меняет сразу), «Готово» — закончить эту; «Удалить дорогу» —
  затем коснуться дороги. Каждая точка — отдельный шаг «Отменить». Дорога из одной точки в файл не попадает.
- Соединение (с 0.42, BF-056): концы дорог — белые кольца. Касание у конца (ближе 3 м) — продолжить ту дорогу;
  точка у конца другой дороги встаёт точно в него, на асфальте другой — на её ось, и дорога заканчивается сама;
  новая дорога, начатая на чужом асфальте, начинается с его оси.
- Крутой поворот (с 0.44, BF-058): точка, после которой дуга на угле (новом или предыдущем) выходит меньше
  `GameWorld.LINE_MIN_R` (улица 5 м, трасса 10 м, мост 6 м), не ставится — «Слишком крутой поворот для трассы —
  поставь точку дальше» (`too_sharp`). Поворот 90° трассы ставится, если отрезки до и после угла ≥ 20 м.
- «Выбор»: объект тянется полупрозрачной копией, сам встаёт на место, когда палец отпущен (BF-055).
- Скорость (BF-055): дома, крыши и двери пересчитываются, только если правка задела клетки домов; вода — если
  задела воду. Вид дома — по его левому верхнему углу, не по номеру.
- «Отменить» — до 60 шагов. «Крыши» — показать/убрать. «Поворот» — вид на 90°. «Из игры» (два нажатия) —
  заменить черновик картой, которая сейчас в игре.
- Кнопка размера («100×100», с 0.36, два нажатия) — увеличить карту до следующего шага: 200, 300, 400, 500.
  Город остаётся в левом верхнем углу (координаты, двери, объекты и точка появления не сдвигаются — сохранения
  игроков остаются верными), новое место справа и снизу — трава. Только больше; «Отменить» этот шаг не
  отменяет (вернуть — «Из игры»). Карта в игре станет больше, когда черновик выпустят.
- «Сохранить» — черновик `user://map_draft.json` (ещё сам раз в 30 с и при выходе). «Пройтись» — офлайн-игра
  на черновике без сохранения, из паузы «Вернуться в редактор».
- «Отправить» — черновик в Supabase `map_drafts`. Правило базы (RLS) принимает только аккаунты из `admins`;
  у остальных — отказ, даже если взломать приложение. Игроки карту не меняют никак: сервер её не принимает.

**Как Claude выпускает черновик** (владелец пишет «выпусти карту»):
1. Supabase: `select id, created_at, note, data from map_drafts order by id desc limit 1;` → сохранить `data`
   в файл (вне репозитория).
2. `python3 docs/tools/map_format.py draft.json > maps/city.json` (тот же формат, проверка символов).
3. `--audit`: карта читается, точка появления свободна, все комнаты достижимы, к мебели можно подойти, окна
   не упираются во внутренние стены. Если тест ругается на саму карту — сказать владельцу, что и где поправить
   (координаты), а не переделывать молча.
4. Снимки (`--demo=editor`, игра), `git diff maps/city.json` — понятно, что поменялось. Коммит «0.N: новая карта
   (что изменилось)», выпуск как обычно.

## 7. Частые ошибки — как не наступить

Карта файлов, связей и критичных мест — **`docs/PROJECT_MAP.md`**.
Структура базы Supabase (таблицы, RLS, права, функции, миграции, замечания аудита) — **`docs/SUPABASE_MAP.md`**.
Какие данные куда ходят (телефон ↔ сервер ↔ Supabase ↔ GitHub), утечки и дублирование — **`docs/DATA_FLOW.md`**.
Что покрыто автотестами, что нет, какие проверки ненадёжны — **`docs/TEST_COVERAGE.md`**.
Полная история ошибок, причин и исправлений — **`docs/BUGFIX_LOG.md`** (журнал BF-NNN). Перед исправлением —
поиск похожего в журнале; после исправления — новая запись в том же коммите. Старые записи не удаляются.

| Ошибка | Чем грозит | Как правильно |
|---|---|---|
| Логика действия только на телефоне | Читы: деньги, предметы, телепорт | Считать на сервере, телефон только просит |
| Новое поле без значения по умолчанию | Старые сохранения не загрузятся, мир пропадёт | `o.get("поле", умолчание)` |
| Отправить всем `player_data()` | Утечка денег/вещей, а с `uids` — угон персонажей | Другим — `player_public()` |
| Лаунчер вызывает класс игры | После обновления работает старый код | Только `Engine.set_meta` |
| Автозагрузка (autoload) | Не обновится пакетом | Узел создаётся в `main.gd`, доступ через статическую ссылку |
| Удалить/потерять ключ подписи APK | Новый APK не встанет поверх старого → переустановка → потеря аккаунта | Ключ — в секретах GitHub (`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASS`); сборка сверяет его отпечаток и без него останавливается, новый ключ сама не создаёт (BF-037) |
| Пуш с упавшим тестом | Релиза не будет | Сначала `--audit` локально |
| Длинные операции в `_process` сервера | Тормоза у всех | Сервер раз в минуту пишет «онлайн N, кадр X мс (худший Y), кадров/с, отправлено КБ/с, память» (с 0.33; `--stat=N` — чаще) — средний кадр держать < 10 мс |

## 8. Известные ограничения и долги

- Игровые данные (деньги, вещи, позиция) хранит игровой сервер в файле мира, а не Supabase. Перенос в базу — позже.
- **Канал игры зашифрован (DTLS, с 0.24), с 0.27 телефон сверяет сертификат сервера** (BF-038): подслушать и
  подменить сервер посередине (свой Wi-Fi) нельзя. Ключ сервер создал сам: `/srv/umwelt/data/godot/app_userdata/
  Umwelt RP/dtls/dtls.key` (секретный, **не удалять** и не публиковать) и `dtls.crt` (публичный — он вшит в игру,
  `Net.SERVER_CERT`, SHA-256 `19:E2:A7:FF…A9:88:D7:E3`; прислан владельцем 2026-11-04). Только для 127.0.0.1
  (тесты, CI) сверки нет. Перед каждым выпуском CI (шаг «Server certificate», `docs/tools/probe_server.gd`)
  подключается к боевому серверу и останавливает выпуск, если сертификат не совпал; если сервер не отвечает —
  только предупреждение. **Если `dtls.key` удалён или сервер переставлен** — сервер создаст новый ключ, и все
  телефоны перестанут подключаться: прислать новый `dtls.crt` (`cat "…/dtls/dtls.crt"` по SSH), Claude вшивает,
  выходит версия; до этого игра недоступна. Перенося сервер — переносить и папку `dtls/`.
- **Секреты GitHub** (Settings → Secrets and variables → Actions): `ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASS` —
  ключ подписи APK (отпечаток SHA-256 `0623ae80…c84ba34c`, полностью — в `build.yml`); `BOT_PASSWORD` — пароль
  тестового бота. Перенесены 2026-11-04 разовой сборкой `migrate-secrets.yml` (ветка `secrets-migration`, в `main`
  её нет) с временным токеном владельца `SECRETS_PAT` (токен и секрет потом удалены). Копию ключа владельцу стоит хранить и вне GitHub —
  сейчас её нет (ключ только в секретах; оттуда его прочитать нельзя, только использовать в сборке).
- **Подпись обновлений на сервере** (BF-039): `server/update.sh` в репозитории с 2026-11-04 проверяет `manifest.sig`
  (`openssl dgst -sha256 -verify`, открытый ключ вписан в сам скрипт) и без верной подписи не обновляется. Но
  скрипт стоит на самом сервере (`/usr/local/bin/umwelt-update`, ставится `setup.sh` один раз) — изменения в
  репозитории туда сами не попадают. **Поставлен владельцем 2026-11-04** (проверка `grep -c "openssl dgst"` — 1,
  запуск — код 0). Ставить заново (если скрипт изменится) — по SSH одной командой:
  `curl -fsSL https://raw.githubusercontent.com/C0BecTb11/Umwelt-RP/main/server/update.sh -o /usr/local/bin/umwelt-update && chmod +x /usr/local/bin/umwelt-update`,
  потом `umwelt-update` — должно молча закончиться (сборка та же) или обновить; «Подпись манифеста не сошлась» на
  свежем релизе — повод разбираться. Пока не поставлен — сервер сверяет только sha256 из манифеста. Если когда-нибудь
  сменится ключ подписи APK, ключ в `update.sh` тоже менять и ставить скрипт заново, иначе сервер перестанет обновляться.
- **Сборки из чужих форков** (Settings → Actions → General → «Approval for running fork pull request workflows»):
  «Require approval for all external contributors» — включено владельцем 2026-11-04 (по его словам; отсюда
  настройки Actions не читаются). Чужой pull request не запустит сборку без одобрения владельца.
- **Город пока тот, что строил генератор из Zomboid** (с 0.19 он записан в `maps/city.json` и правится в
  редакторе), не 90-е. Следующий этап — свой городок. Размер карты пока 100×100: больше — после подгрузки
  районов частями (иначе слабые телефоны не потянут). Объекты пока простые модели из кода (`props.gd`) —
  модели художника встанут на их место (поле `scene` в каталоге).
