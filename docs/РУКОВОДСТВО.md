# Umwelt RP — руководство проекта

Мобильная РП-игра (Android) в духе SAMP RP. Сеттинг: Америка, 1990-е. Движок: Godot 4.4.1 (GL Compatibility).
Документ обязателен к прочтению перед любой работой и **обновляется вместе с кодом**: поменял правило, механику или
способ сборки — поправь этот файл в том же коммите.

---

## 1. Как всё устроено

```
 Телефон                                   GitHub                         Hetzner (2.31.45.237)
┌──────────────────────┐   HTTPS   ┌──────────────────────────┐  раз в   ┌──────────────────────────┐
│ umwelt.apk = лаунчер │ ◄──────── │ Releases → «latest»       │ 2 мин    │ umwelt-update (таймер)   │
│ + встроенная игра    │  manifest │  manifest.json            │ ───────► │ скачивает сервер, сверяет│
│ скачивает game.pck,  │  game.pck │  game.pck                 │          │ SHA-256, перезапускает   │
│ проверяет SHA-256,   │           │  umwelt-server.zip        │          │                          │
│ подключает и играет  │           │  umwelt.apk               │          │ umwelt-server (Godot     │
└─────────┬────────────┘           └────────────▲─────────────┘          │ без графики), порт 7777  │
          │  ENet UDP 7777                       │ пуш в main → сборка   └────────────▲─────────────┘
          └──────────────────────────────────────┼────────────────────────────────────┘
                                                 │
                                       .github/workflows/build.yml
```

- **Вся игровая логика — на сервере** (`scripts/server_only/server.gd` + `scripts/game.gd`). Телефон присылает ввод (куда идёт)
  и действия («ударить», «взять»), сервер всё проверяет и рассылает результат.
- Свой персонаж двигается на телефоне сразу (предсказание), сервер принимает позицию, только если она честная
  (скорость, стены, двери). Нечестную откатывает (`push_player`, номер отката `force_seq`).
- Чужих игроков телефон рисует с небольшой задержкой между двумя пакетами (`NetClock`, `sample_snaps`) —
  поэтому без рывков даже на плохом интернете.
- **Обновления без переустановки**: APK — это лаунчер со встроенной игрой. При запуске он сверяется с
  `manifest.json` в релизе «latest» и докачивает `game.pck` (новая версия кода и ресурсов игры).
- **Сервер обновляется сам**: таймер на Hetzner раз в 2 минуты смотрит манифест и при новой сборке ставит её.

## 2. Структура репозитория

| `scripts/net.gd` | Сеть ENet (`Net.I`) — и для сервера, и для клиента |

| `scripts/items.gd` | Все предметы, одежда, слоты, таблицы лута |

| `scripts/profile.gd` | Настройки телефона: старый uid (для офлайна и переноса персонажа), графика |

| `server/setup.sh`, `update.sh` | Установка и автообновление сервера на Hetzner |
| `.github/workflows/build.yml` | Сборка и выпуск |
| `NEWS.md` | Первая строка показывается в лаунчере как новость |

## 3. Как выходит обновление

1. Изменения попадают в ветку `main`.
2. GitHub Actions (`build.yml`): автотесты → `game.pck` → сервер → APK (если нужно) → релиз «latest».
   **Если хоть один тест упал — релиза не будет.** Лог упавшей сборки — в ветке `buildlog`.
3. Игроки: при следующем запуске лаунчер скачает обновление.
4. Сервер: в течение ~2 минут сам скачает и перезапустится (игроков на эти секунды выкинет — это нормально).
   Если телефон успел обновиться раньше сервера, игрок увидит «Сервер обновляется — зайди через пару минут».

### Когда нужен новый APK
Определяется **автоматически** (по «отпечатку»): изменился `launcher/`, `project.godot`, `export_presets.cfg`,
версия Godot или **появился/пропал/переименован `class_name`**. Тогда собирается новый APK, и лаунчер у игроков
покажет «Скачать новую версию приложения». Новый APK ставится поверх старого — персонаж и настройки сохраняются.
Совет: новые классы без нужды не делать (`class_name`), вспомогательные скрипты подключать через `preload`.

### Версия игры
Версия = `0.<номер сборки>` (номер запуска CI, он же `Version.BUILD`). Видна в углу лаунчера и в меню паузы.
Сервер пускает только клиента той же сборки.

### Напоминания об обновлении
- Лаунчер при старте сам скачивает обновление; если нужно новое приложение — показывает кнопку «Скачать новую версию».
- В игре раз в 3 минуты проверяется манифест; если вышла сборка новее — сообщение и постоянная плашка под часами
  «Доступно обновление 0.N — закрой и открой игру». После выхода в лаунчер он тоже это напомнит.
- Системные уведомления Android (в шторке) пока не делаем — для них нужен Android-плагин и новый APK.

## 4. Правила кода (обязательные)

1. **Сервер решает всё.** Любое новое действие игрока:
   - добавить в `GameState.valid_action()` с проверкой типов полей;
   - в обработчике проверить расстояние (`near_cell`), наличие предмета, состояние (жив, не лезет в окно);
   - написать автотест «нельзя сделать нечестно» в `audit_test.gd`.
2. **Никаких автозагрузок (autoload).** Сеть — `Net.I`, профиль — `Profile`. Автозагрузки не обновляются пакетом.
3. **Лаунчер не трогает классы игры** (`Version`, `Boot`, `Net` и т.д.) — иначе после подключения пакета
   в памяти останется старая версия. Данные в игру — только через `Engine.set_meta`.
4. **Новое поле у игрока или мира** → добавить в `player_data()`/`player_from()` (или `to_data()`/`load_data()`)
   со значением по умолчанию через `.get(ключ, умолчание)`. Если меняется смысл старых данных — поднять
   `SAVE_VERSION` и дописать шаг в `migrate()`. Старые сохранения сервера должны загружаться всегда.
5. **Приватность.** Другим игрокам уходит только `player_public()` (имя, одежда, в руках, без сознания).
   Деньги, инвентарь, здоровье — только самому игроку. Карту аккаунтов `uids` не отправлять никому:
   uid — это ключ от персонажа.
6. **Позиции и ввод — канал 1, надёжный** (`Net.I.send_fast`). Не переводить на «ненадёжный»: ENet тогда
   выкидывает пакеты сериями по секунде (проверено замерами — друг «замирал» и прыгал).
7. **Каждый найденный баг** — сначала тест, который его ловит (должен упасть на старом коде), потом исправление.
8. **Серверное — только в `scripts/server_only/`.** Эта папка не попадает в APK и пакет игры (фильтр экспорта
   Android), сборка проверяет это сама и падает, если серверный код утёк. Сюда — вход/аккаунты, админка,
   античит, экономика, всё, что игроку видеть не нужно. Подключать только через `load("res://scripts/server_only/…")`,
   без `class_name`. Общие правила игры (движение, предметы) — в `game.gd`: они нужны и телефону.
9. **Никаких секретов в коде клиента.** В игре могут быть только публичные данные (адрес сервера, publishable-ключ
   Supabase). Пароли, сервисные ключи, токены — только на сервере (файлы вне репозитория) или в секретах GitHub.
   Всё, что лежит в APK, считаем прочитанным: его разбирают готовыми программами.
10. **Карточка игрока.** Всё, что принадлежит игроку (наличные `money`, банковский счёт `bank`, вещи,
   одежда, а дальше — машины, дома, работа, фракция, лицензии), — поле класса `GameState.Player` и
   сохраняется в `player_data()`. Отдельных словарей «игрок → что-то» в стороне не заводить. Если вещь живёт
   в мире (машина на улице, дом), у неё поле `owner` = **ID игрока**, а не имя и не uid.
   ID постоянный: для аккаунта это `characters.id` из Supabase, у игроков без аккаунта — от 1 000 000.
   В текстах для игроков имя пишется через `GameState.tag(p)` → `John_Miller (5)`.
11. Тексты для игрока — по-русски. Комментарии в коде — по-русски, коротко и по делу.

## 6. Сервер (Hetzner CPX02: 1 ядро, 1 ГБ, общий с sw-rpg)

**Установка (один раз, от root, в консоли Hetzner или Termius):**
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/C0BecTb11/Umwelt-RP/main/server/setup.sh)
```
Скрипт безопасно запускать повторно. sw-rpg он не трогает.

| Что | Где |
|---|---|
| Игровой сервер | `/srv/umwelt/server/` (пользователь `umwelt`, служба `umwelt-server`) |
| Мир и персонажи | `/srv/umwelt/data/godot/app_userdata/Umwelt RP/server_world.json` (+ `.bak.json`) |
| Автообновление | `/usr/local/bin/umwelt-update`, таймер `umwelt-update.timer` (каждые 2 мин) |
| Порт | 7777/UDP. Если у сервера включён фаервол Hetzner (вкладка Firewalls) — добавить правило Inbound UDP 7777 |
| Лимит памяти | 450 МБ (`MemoryMax`), чтобы игра не задавила sw-rpg. Swap 1 ГБ создаётся, если его не было |

Полезные команды:
```bash
journalctl -u umwelt-server -f          # журнал (входы, выходы, онлайн, время кадра)
systemctl restart umwelt-server         # перезапуск
systemctl status umwelt-server
journalctl -u umwelt-update -n 20       # что делал автообновлятор
cp "/srv/umwelt/data/godot/app_userdata/Umwelt RP/server_world.json" ~/backup-$(date +%F).json   # бэкап мира
```
Мир сохраняется раз в минуту и при каждом выходе игрока (через временный файл, с резервной копией).

## 6а. Аккаунты (Supabase, проект `Umwelt-RP`, id `fhsjkenwbgncajzjvcxx`)

- **Регистрация и вход** — по почте и паролю, прямо в игре после кнопки «Играть». Пароль уходит только в
  Supabase по HTTPS. Сессия (refresh-токен) хранится в `user://account.cfg`, повторно входить не нужно.
- **Персонаж** — таблица `public.characters` (`user_id`, `name`, `id`). `id` — постоянный номер игрока
  (выдаёт база по порядку, не меняется и не переиспользуется), виден в скобках у ника: `Epson_Drowe (2)`.
  На сервере это ID карточки `Player`; если у игрока раньше был другой номер, карточка со всем
  содержимым переезжает на номер из базы (`join_player` → `_rekey`). Имя `Имя_Фамилия` латиницей
  (проверка формата и уникальности — в самой базе). Изменить имя может только админ (в базе).
  RLS: игрок читает и создаёт только свою строку.
- **Вход на сервер**: телефон шлёт в `hello` токен доступа. Сервер сам спрашивает Supabase
  (`/auth/v1/user`, затем свою строку в `characters` тем же токеном) — **секретные ключи серверу не нужны**.
  Аккаунт на сервере — ключ `sb:<user_id>` в `uids`. Персонаж, созданный до аккаунтов на этом телефоне
  (старый uid), при первом входе переходит к аккаунту.
- Вошли в аккаунт с другого телефона — первое подключение закрывается («вошли с другого устройства»).
- Локальные тесты сервера без аккаунтов: ключ `--noauth` (на настоящем сервере его нет!).
- Тестовый аккаунт для автопроверки: `bot@umwelt-rp.test`, персонаж `Test_Bot` (пароль — в `auth-test.yml`).
- Подтверждение почты: если в Supabase включено «Confirm email», после регистрации игрок видит
  «Мы отправили письмо…». Встроенная почта Supabase отправляет мало писем в час — для запуска нужен свой SMTP
  (Authentication → Emails → SMTP).
- Где смотреть: Supabase → Authentication → Users (аккаунты), Table Editor → characters (персонажи).
- **Ссылка из письма** ведёт на страницу «Почта подтверждена»: ветка `gh-pages` (файл `index.html`),
  адрес https://c0bectb11.github.io/Umwelt-RP/. Он должен стоять в Supabase → Authentication →
  URL Configuration → **Site URL** (иначе письмо ведёт на `localhost:3000`). Pages включается в настройках
  репозитория: Settings → Pages → Deploy from a branch → `gh-pages` / `root`.

## 7. Частые ошибки — как не наступить

| Ошибка | Чем грозит | Как правильно |
|---|---|---|
| Логика действия только на телефоне | Читы: деньги, предметы, телепорт | Считать на сервере, телефон только просит |
| Новое поле без значения по умолчанию | Старые сохранения не загрузятся, мир пропадёт | `o.get("поле", умолчание)` |
| Отправить всем `player_data()` | Утечка денег/вещей, а с `uids` — угон персонажей | Другим — `player_public()` |
| Лаунчер вызывает класс игры | После обновления работает старый код | Только `Engine.set_meta` |
| Автозагрузка (autoload) | Не обновится пакетом | Узел создаётся в `main.gd`, доступ через статическую ссылку |
| Удалить/потерять ключ подписи APK | Новый APK не встанет поверх старого → переустановка → потеря аккаунта | Ключ в кэше GitHub, CI раз в неделю его «освежает»; перенести в секреты (п. 8) |
| Пуш с упавшим тестом | Релиза не будет | Сначала `--audit` локально |
| Длинные операции в `_process` сервера | Тормоза у всех | Сервер пишет «кадр N мс» раз в минуту — держать < 10 мс |

## 8. Известные ограничения и долги

- Игровые данные (деньги, вещи, позиция) хранит игровой сервер в файле мира, а не Supabase. Перенос в базу — позже.
- Токен доступа идёт на игровой сервер по незашифрованному ENet. Он живёт час и годится только для входа
  в этот аккаунт; к монетизации — шифрование канала (DTLS).
- **Трафик игры не шифрован** (ENet). Для РП без платежей допустимо; к монетизации — DTLS или токены сессии.
- **Ключ подписи APK хранится в кэше GitHub Actions**, а не в секретах (секреты отсюда задать нельзя).
  Сделать вручную: Settings → Secrets → добавить ключ, и переключить `build.yml` на секреты.
- **Город пока генерируется кодом из Zomboid** (`world.gd`), не 90-е. Следующий этап — свой городок.
- Механики Zomboid из игры убраны: обыск мебели и машин, вещи на земле, разбивание окон (кнопка действия есть
  только у дверей; «Выбросить» уничтожает вещь). В коде остались спящие куски: перелезание через разбитое окно
  (окна теперь не бьются, так что не срабатывает), режим «зомби» в `character.gd` (пригодится для NPC),
  баррикады в `world.gd`/`world_mesh.gd`, таблицы лута в `items.gd`. Удалять при случае, не трогая рабочее.
- iOS не собираем и не планируем, пока не решено отдельно.
- Внешность персонажа одна на всех (цвета по номеру) — нужен редактор персонажа.
- Сервер: проверено 10 одновременных игроков локально (кадр 1.7–3 мс). На 1 ядре CPX02 ожидаемо 50–100;
  для сотен — тариф больше и раздельные «зоны видимости» (уже есть: игрок видит других в радиусе 40 клеток).

## 8а. Защита кода
- Репозиторий пока **публичный** — весь код виден. Решено отложить; план: закрыть репозиторий, а сборки выкладывать
  в отдельный публичный `Umwelt-RP-builds` (нужен токен `RELEASES_TOKEN` в секретах).
- Код из APK можно разобрать (у любой игры) — поэтому правила 1, 8, 9: решает сервер, серверное не уходит
  к игрокам, секретов в клиенте нет.
- `LICENSE`: все права защищены — основа, если кто-то поднимет копию сервера.
- Позже по желанию: шифрование пакета игры (своя сборка движка Godot с ключом) — усложняет разбор, но не исключает.

- **Постоянный ID и карточка игрока**: у каждого персонажа номер из базы (`characters.id`), показан в скобках
  у ника и у себя рядом с деньгами; банковский счёт `bank` добавлен в карточку; правило 10 «всё игрока — в
  карточке». Тесты на переезд карточки и сохранение счёта.
- **Защита**: серверный код вынесен в `scripts/server_only/` и не попадает к игрокам (проверка в сборке),
  LICENSE «все права защищены», правила 8–9 в руководстве.
- **Аккаунты**: регистрация/вход по почте через Supabase, создание персонажа Имя_Фамилия, сервер проверяет
  токен в Supabase, старые персонажи переходят к аккаунту, автопроверка входа в CI.
- **Чистка от Zomboid и лаунчер**: убраны обыск, вещи на земле, разбивание окон; заставка Godot при запуске;
  лаунчер стал стартовым экраном (название + «Играть» + «Офлайн-тест» + версия), меню в игре убрано;
  напоминания об обновлении в игре; новая иконка в стиле 90-х.
- **Сервер установлен** на Hetzner (setup.sh), сборка 3 запущена, порт 7777/UDP открыт в ufw.
- **Сборка 1** — старт проекта из движка Zomboid: убраны зомби, медицина, баррикады; деньги, нокаут вместо
  смерти (очнуться у больницы через 20 с); драки и стрельба между игроками на сервере; выделенный сервер
  на много игроков; лаунчер с обновлениями из GitHub Releases; автоустановка и автообновление сервера.
